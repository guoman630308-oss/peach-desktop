# ADR-0053：结算到底就派后继，存量缺图的每轮补派一截

- 状态：Accepted
- 日期：2026-09-24
- 修订：ADR-0040 第四条、第七条

## 背景

补头像后继（ADR-0040）与补厂牌后继（ADR-0052）上线之后，`task_run` 里 `entity-avatar`
一行都没有。上线后的六轮处理任务，三轮 `failed`、三轮 `interrupted`，成功零轮；那三轮
`failed` 的原因只是「256 项需要处理，其中 27 项是来源限流」这类留给人的待处理项。
`process_library` 结算时写 `status='failed' if issue_count else 'complete'`，而 ADR-0040
第四条规定父任务失败一条后继都不派，于是两条后继从来没有跑过。

第二个缺口在派单范围：后继只派给「这一轮新登记的实体」和「这一轮换了封面的作品上的
女优」。全库没头像的 211 位女优里，175 位是在后继上线之前登记的，就算以后每一轮都成功，
也永远轮不到她们。其中 76 位的单人作品封面上就截得出脸。

## 决策

**一、声明了后继就派，与父任务的状态无关。** 处理任务只在结算到底的那一刻声明后继；
途中抛异常的轮次走不到那一步，`BackgroundJob` 在异常路径上还会把途中的声明清空。所以
「有没有声明」本身就是「这一轮有没有跑完」的判据。留下待处理项的那一轮照旧记成
`failed`，活动页上那一行的结论不变，后继照派。ADR-0040 第四条的另一半不变：后继失败
不改判父任务。

**二、名额先给新实体，余下的给存量。** 每轮至多 `MAX_FOLLOWUPS`（64）条：新登记的先排，
再按作品数从多到少补上库里至今缺图的女优（没有头像，或装着的是封面截图与整张封面），
最后是盘上没有标识的厂牌。存量每轮往前推一截，不需要另跑一次性的批处理。

**三、试过又没变的不再派。** 存量里找不到图的实体每轮都还缺图，只看「缺不缺」会让同一批
每轮都把名额占满。后继跑完记下实体当时的指纹：女优是作品数，厂牌是作品数与官网、目录
链接数。指纹没变就不再派，多一部作品或多一条链接就再试一次。记号落在
`generated/provider-cache/followup-attempts/`，一件事一个文件；任务记录每类只留 20 行，
存不住这份记号。

## 后果

- 下一轮处理任务结算时，新实体加存量共 64 条后继开始跑：先是作品多的缺图女优，再是厂牌。
- 封面截脸、图库唯一命中这两档判据一个字没变；图库同名多张、别名没统一的那些仍装不上，
  需要各自的判据（别名导入、人脸比对），不在本 ADR 内。
- 删掉 `followup-attempts/` 下的文件，就等于让那些实体在下一轮重新排队。
