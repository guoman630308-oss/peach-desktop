# ADR-0029：本地 NFO 给出的字段免复核补空

- 状态：Accepted；补空的边界由 ADR-0033 推广到账本已有值的字段；NFO 在线核查与覆盖复核见 ADR-0108
- 日期：2026-09-14

## 背景

既有库采集先读视频旁的 NFO，再向 r18.dev 补缺。NFO 多由 JavBoss、Javinizer 等刮削器写下，
用户自己跑过一遍，写法是日文原题与日文艺名。

独立包读桌面 JAV 文件夹实测（`ABW-358`）：

- r18.dev 的 `dvd_id` 入口只给英文，标题是机翻（`title_en_is_machine_translation` 为真），
  演员只有罗马字；
- 采集照样向 r18.dev 要全部字段，于是标题、系列同时出现 NFO 与 r18dev 两条候选，取值
  一日一英，被 ADR-0025 判成分歧，进人工复核；
- `local_nfo` 不在 `REGISTERED_SOURCES`，自动落库先把它剔除，只剩 r18dev 一条，结果英文
  机翻值被自动写进账本，NFO 的日文值反而要人去复核里点。

决定：元数据优先日文，准确的 NFO 不必再审。

## 决策

**一、NFO 已给出的字段只收 NFO 这一条候选。** 在线来源只补 NFO 没有的字段；重跑时 NFO
那一条会清掉同字段的其他来源候选。

**二、`local_nfo` 构成补空证据。** `metadata_auto_apply_candidate` 放行 `local_nfo`
候选，其余条件不变：字段为空、取值去重后唯一、番号在该番号每条资产的文件名里、字段归属
不是用户判断。`note.rule` 记 `adr-0029-empty-field-local-nfo`。

**三、r18.dev 补日文写法。** 取到 `content_id` 后再请求 `combined=<content_id>` 页，把
`title_ja`、`series_name_ja`、`label_name_ja` 与首位导演 `name_kanji` 组成 `ja` 翻译，
演员改用 `name_kanji`。厂牌仍用英文品牌名：账本厂牌实体是 `Prestige`、`MOODYZ`，写
`プレステージ` 会另起实体。combined 页取不到时退回英文。

NFO 的身份门槛沿用采集时已有的一条：NFO 自报番号与文件名番号不一致，整条停下交人工。

## 理由

- NFO 与文件是同一个人放在一起的，番号又对过文件名，它对「这个值属不属于这部片」的证据
  不弱于任何在线来源。
- 英文机翻与日文原题的差异是写法，不是事实分歧；把它交给人判断只是在消耗复核。
- 补空不覆盖任何东西，ADR-0018 要防的风险面没有被触碰。

## 被否决的方案

- **设置里加「优先采用本地 NFO」开关。** 两种取值下都要维护一套行为，而关掉它的唯一
  结果是回到上面那种一日一英的复核题，没有用户需要这个状态。
- **拿 NFO 的时长、发行日期和在线来源比对后才放行。** 在线来源对素人、下架片常常没有数据，
  那样 NFO 越有用的地方越被扣住；时长还受切片、合并文件影响，误判面大于收益。
- **厂牌也取日文。** 与现有厂牌实体的规范名冲突，需要实体层先有别名合并。

## 后果

- NFO 覆盖的字段不再进人工复核；NFO 没给的字段仍按 ADR-0018/0025 处理。
- `review_decision` 中出现 `rule` 为 `adr-0029-empty-field-local-nfo` 的行，字段归属记
  `auto:local_nfo`。
- 已被在线来源写入的值不会被 NFO 覆盖；要换成 NFO 值须在详情页或复核里手动改。
- 采集每部片对 r18.dev 多一次请求。
