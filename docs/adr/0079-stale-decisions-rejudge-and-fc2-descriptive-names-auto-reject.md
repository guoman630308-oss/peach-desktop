# ADR-0079：过期决定交自动落库重判，FC2 描述性称呼自动否决

- 状态：Accepted
- 日期：2026-09-27
- 相关：ADR-0018、ADR-0052、ADR-0054、ADR-0072
- 修订：ADR-0082 让决策二里人批准的标签只增不删，并让带 `pending_genres` 的行在词收录后按并集补标签；ADR-0086 让决策三里 `Xちゃん` 与另一家 `X` 并列的行算两家一致

## 背景

按 ADR-0052，已有确定结论的重复项无需再次交人：

- **过期批准。** 用户批准过某个候选，后来来源给出新候选、原 `candidate_key` 不在
  当前候选里，复核页就按过期把它摆回待定。可过期判据只写在复核页（`web_review`），自动
  落库那一侧不认它：过期行既不重判也不落，只能等人再点一次。
- **FC2 描述性称呼。** FC2 卖家在出演者栏写 `みおちゃん`、`神スタイルの現役グラドル`
  这类称呼。ADR-0054 定了它们不建女优实体，但落不下的行仍然交人工，人能做的只有逐条否决。

## 决策

**一、过期判据只有一份，放在领域层。** `metadata_auto_apply.metadata_decision_is_stale`
按状态分三种：approved 的 `candidate_key`（及追加的 `refreshed_candidate_key`）都不在当前
候选里算过期；带 `auto_rejected` 的 rejected 在当前候选出现否决时没有的 key 算过期；用户手工
否决、跳过与自由文本 note 一律不算过期。复核页与 `auto_apply_metadata` 调同一个函数。

**二、过期的批准按下面的规则重判，不改写人的留痕。**

| 重判结果 | 原决定 | 做法 |
| --- | --- | --- |
| 与账本现值相同（标签按集合、出演者与厂牌系列按实体身份比） | 任意 | 真相不写；status、updated_at 与 note 原项不动，只追加 `refreshed_candidate_key` |
| 会改值 | 自动落库的（note 有 `auto_applied`） | 照常重落，覆盖那条决定 |
| tags 是账本现值的真超集 | 人批准的 | 只插新增的标签，归属 `auto:metadata-tags@<时间>`；note 追加 `refreshed_candidate_key` 与 `added_tags` |
| 其余会改值的 | 人批准的 | 不落，留在复核页交人 |

note 带 `pending_genres` 的行照旧跳过。

**三、FC2 番号的 performers，全部候选里每一位都剪不出艺名、企划名义也解不出时，自动写
`rejected`。** note 记 `auto_rejected: true`、`rule: adr-0079-fc2-descriptive-performer`、
`candidate_keys` 与 `rejected_values`；不建实体、不写真相字段。部分候选剪不出时剔掉那几条，
剩下的照常判，被剔的记进落库 note 的 `descriptive_dropped`。以下情况仍交人工：一条候选里真名
与称呼混写的；剔完只剩两字短名的（ADR-0072 所说的会命中别人）；人批准过的行。非 FC2 番号
不适用本条。

**四、两类自动决定都能按来源整批撤回。** `revert_auto_landing.py --source
adr-0079-fc2-descriptive-performer` 删掉这批否决、行回到复核页；`--source auto:metadata-tags`
只删并集补进的那几行标签并去掉 note 里追加的两项。决定没有批次号，给了 `--batch` 时一条都
不认。撤回前要先改判据，否则下一轮处理任务会原样再做一次。

## 理由

- 判据分两份时，复核页说「过期」而落库说「已决定」，行就卡在两者之间，人再点一次也只是
  重复来源已给出的结论。
- 人批准的是当时那一个候选。来源更新后值没变，重写 note 只会抹掉「这是人确认过的」；值要变，
  就是自动写入者要改人的判断，ADR-0052 不允许。标签只增不减是例外：人判过的标签一个不少，
  新增的只是补空。
- 描述性称呼没有可建的实体，也没有可落的值，交给人只有一个答案：否决。

## 被否决的方案

- **过期批准一律重落。** 会把人工批准改写成 `auto_applied`，丢失人工留痕。
- **账本一侧只拿同一来源的标签比超集。** 这需要额外的来源过滤，也无法保护其他来源或人工确认的标签。
- **称呼也建实体、等以后合并。** ADR-0054 已否决：称呼不指向某一个人，合并时无从判断。

## 后果

- 处理任务摘要多出 `auto_rejected` 与 `refreshed` 计数；界面卡片仍只显示自动落库数。
- 两个批次先后给同一行补标签时，note 的 `added_tags` 只留最后一次；撤前一批会让行回到队列，
  后一批补的标签仍在账本里。
