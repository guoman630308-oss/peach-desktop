# ADR-0011：Windows 托盘拥有登录后运行态

- 状态：Accepted
- 日期：2026-08-15

## 背景

Peach 是单用户本地自托管应用，但此前 HTTP/HTTPS 只能由终端手动启动。主机没有 Peach
系统服务、计划任务、Startup 快捷方式或注册表 Run 项，重启或退出会话后自然不可用；用户也
缺少直观的运行状态和退出入口。

Windows 服务运行在非交互会话，不能可靠承载通知区 UI。计划任务或另一个后台守护进程再
启动托盘会形成双重生命周期和重复服务所有权。

## 决策

- 使用当前用户 Startup 快捷方式，在登录后直接运行项目 venv 的
  `pythonw.exe -m peach.tray`。
- 复用 pystray 0.19.5 的 Windows 通知区实现；左键默认动作打开 Peach，右键显示原生菜单。
- 托盘作为唯一日常进程所有者，同时启动 HTTP/mDNS 和 HTTPS 服务，输出写入运行数据日志；
  文件锁阻止重复托盘。
- 退出和重启只作用于托盘自己创建的子进程。已由其他入口启动的健康服务不会被托盘误杀。
- 更新检查只读本地版本和更新通道；没有 Git remote 时明确报告「未配置更新源」，不自动拉取、
  合并或覆盖本地修改。
- 安装、检查和卸载 Startup 快捷方式统一走 `scripts/manage_tray_startup.ps1`。

## 已拒绝方案

- **Windows 服务承载托盘**：会话隔离，不适合交互 UI。
- **计划任务加独立托盘**：重复生命周期、退出语义不清。
- **注册表 Run 项**：可见性和可检查性不如 Startup 快捷方式。
- **自研 Win32 通知区协议**：pystray 已提供原生菜单和默认动作，重复实现没有产品价值。
- **点击「检查更新」自动覆盖工作树**：个人项目仍有并行 agent 与未提交改动，必须先审核集成。

## 后果

Peach 在用户登录后自动出现一个通知区入口，没有控制台窗口；退出语义明确且可回退。它不是
无人登录也运行的系统级服务器。如果未来需要开机未登录即服务，必须另立后台服务 ADR，并把
服务所有权和托盘控制协议拆开，不能并行启动第二套 Web 进程。
