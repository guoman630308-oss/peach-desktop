# ADR-0063：补别名后继的 av_neme 入口、「未取得」重派与存量名额

- 状态：Accepted
- 日期：2026-09-24
- 修订：ADR-0055 第一条（av_neme 入口）与第二段（存量名额 16 条）、ADR-0053 第三条（试过又没变的不再派）

## 背景

来源冷却期间的「未取得」不能当作永久结论，否则名字链不变就不会再次派发。

av_neme 那一站按账本名字站内检索、只读前三条结果。`叶芽ゆきな` 搜出八页，她的人物页
`桜美ゆきな`（名字栏列着 `叶芽ゆきな`、`夢原まみ`、`尾上さら`）排第六，前五页是 `ガチ素人`、
`Girl's Blue` 这些厂牌页与月份页，每页几十部作品、搜谁都命中。`初川みなみ` 的人物页在二十条
结果里根本排不进去，前面全是提到她的别人的人物页与月份页。两位都判成「没有人物页列着」。
而这个 Wiki 的页面按页名寻址，人物页就叫她的名字，`d/初川みなみ` 一次就到。

## 决策

**一、av_neme 先按页名直取，检索结果按摘要排序。** 每个检索键先取 `d/<名字>`：是人物页且
列着她就用；是改名页（`女優名が【旧】から【新】へ変更`）跟一跳到现页；页不存在再站内检索。
检索结果先去掉页名明显不是人物的（月份、番号、一览、厂牌），再按摘要分三档：像资料栏的
（`旧名義`、`別名`、`生年月日`、`身長`、`プロフィール`）在前，像作品小节的（`名前(女優名)`）
在后，其余按站给的顺序；仍只读前 `MAX_PERSON_PAGES` 页。

**二、「未取得」的记号带有效期。** `followups.Attempts.record` 多一个 `retry_after`，记号里写
`retry_until`；`settled` 在过期后当没跑过。补别名的「未取得」传 `RETRY_UNFETCHED`（24 小时），
其余结论（登记了、没有新写法、都没对上）照旧只看指纹。补头像与补厂牌不传，行为不变。

**三、存量名额是一轮的一半。** `STOCK_SHARE` 为 32。一条要问两三站、十来秒，
走写账本那条串行通道；32 条五分钟，补厂牌那几条仍排在后面，只是晚几分钟。

**四、指纹带入口判据的版本。** `ENTRY_RULE` 进 `fingerprint`，与补头像的 `MATCH_RULE` 同一做法：
入口换了，同一条名字链在站上能到的页就不一样，跑过的女优全部按新入口再问一次。本 ADR 把它定为 2。

## 后果

- 别名已被另一实体占用时，按 ADR-0055 第六条记「占用」进复核产物，合并仍由人决定。
- 直取多花一次请求（改名再一次），一条后继 8 次的预算里一个检索键至多用 5 次；第三个键常轮不到。
- 冷却期间跑到的女优第二天再派；站长期挡着的话，每天这一批各多一次请求，然后再等一天。
- 缺少入口版本的记号不匹配新指纹，按存量名额逐批重派。
- `Attempts` 多一个可注入的时钟，测试不必真等一天。
