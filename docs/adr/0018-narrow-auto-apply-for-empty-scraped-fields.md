# ADR-0018：补空字段在窄条件下免复核直接落库

- 状态：Accepted
- 日期：2026-08-24
- 修订：ADR-0025 把 `AUTO_APPLY_FIELDS` 从 `release_date` 一个字段扩到六个 P0 字段，白名单以代码为准；ADR-0079 规定过期决定怎样重判；ADR-0082 给第 3 条加了文件名读不出番号时的目录名窄兜底

## 背景

`AGENTS.md` 与 ADR-0005 规定：刮削与 AI 结果只能作为带来源和置信度的候选，不直接改写真相
字段。这条规则的目的是防止外部来源在无人知情的情况下改掉账本已有的判断。

实测暴露了它的边界。元数据复核队列 43 条里，10 条是发行日期，全部具备同一组特征：

- 目标字段当前为空，不存在「改掉已有判断」这回事；
- 每条只有一个候选（r18dev，现行 policy 归类为 `official_mirror`），没有第二个值可选；
- 番号逐字出现在文件名里（`PPT-018-1-uncensored.mp4`、`MIDE-925-4K.mp4`、`ABW-220.mp4`）。

界面上摆着「通过 / 跳过 / 拒绝」，但没有可判断的对象：没有备选、没有冲突、没有覆盖风险。
复核在这里不产生判断，只产生点击。

刮削唯一真实的失败模式是番号识别错误：番号错则取值错。但复核界面恰恰帮不上这个忙：
它并排显示番号与日期，并不告诉你番号和这个文件对不对得上。番号存疑由 `code_creators`
那一栏单独承担。

## 决策

新增一条**窄例外**，不是废除 ADR-0005。三项条件必须同时成立，缺一项立刻回到人工：

1. 目标字段当前为空：只补空，永不覆盖既有真相字段；
2. 该字段只有一个候选：出现第二个值就存在取舍，取舍正是复核要做的事；
3. 番号在该番号名下**每一条**资产的文件名里逐字出现（大小写不敏感）。

来源级别不是条件（用户 2026-09-04 决定）。补空不覆盖任何东西，唯一的风险是「这个值属不
属于这部片」，那由第 3 条管，与来源可信度无关。把 `official` 立成条件的代价是实测 76 条
javbus 补空候选全部滞留人工，补的都是账本里空着的发行日期，没有可判断项却要人逐条点过。

适用字段由 `AUTO_APPLY_FIELDS` 显式白名单控制，当前只有 `release_date`。

每条自动落库仍写 `review_decision`，`note` 记录 `auto_applied`、判据标识、候选键、来源与
取值。留痕是 ADR-0005 真正要保住的东西：事后必须答得出「这个值是谁写的、凭什么」。判据
标识按来源实际级别写成 `...-single-official-source` 或 `...-single-community-source`，
两类补空日后要分开回溯时，`note` 是唯一留着这个区别的地方。

**已确认的值不被低一级来源挑战。** 现值由 `official` 源写入、而挑战方只有 `community` 源
的行不进复核队列，账本保留 official 值。没有落库记录的行照常进队列：
现值来路不明时 community 的异议有意义。现值与记录不符（被别的动作改过）时同样交回人工。
**只有记下了取值的记录才算数。** 人工批准写的 note 只有 `candidate_key` 与 `source`，
证明不了账本现在这一个是它写的；拿它当已确认会把 `metadata_decision_is_stale`
本该重开的字段永久压在队列外面。

判据实现见 `metadata_auto_apply_candidate`；执行入口是处理任务收尾时调用的
`metadata_auto_apply.auto_apply_metadata`（调用点在 `library_processing._apply_finished_candidates`），
走正常写事务，因而同样受只读端闸门约束。

## 理由

- 第 1 条把风险面限制在「无中生有」，排除了这条规则最初要防的场景。
- 第 2 条保证没有任何取舍被机器代替人做出。
- 第 3 条是这条捷径唯一的身份保证，且是本机可核验的证据，比复核界面实际能提供的更强。
- 来源级别改由「已确认的值不被低一级来源挑战」承担：它管的是覆盖，而覆盖才是来源可信度
  真正起作用的地方；补空没有被覆盖的对象。

## 被否决的方案

- **对所有字段开放自动落库。** 演员与标签的来源–账本分歧是真实的：r18dev 给日文名，账本
  规范名多已本地化为中文，自动采信会把规范名倒退成别名。这两类必须留在人工。
- **仅凭「来源官方」就落库，不看番号证据。** 那会把番号识别错误静默放大成错误的真相字段。
- **读复核页时顺手落库。** 读接口不得产生写副作用，只读端也会因此报错。
- **完全维持现状。** 让人对没有可判断对象的条目逐个点击，会把真正需要注意力的条目淹掉；
  `_needs_review` 早已对封面与 babepedia 做过同样的取舍。

## 后果

- 符合三项条件的候选不再入队：实测 76 条 javbus 补空的发行日期因此自动落库。
- 现值由 official 写入、只有 community 源提异议的 20 条冲突同样不入队，账本保留 official 值。
- `review_decision` 中出现 `status='approved'` 且 `note.auto_applied=true` 的行；审计时
  可据此把自动落库与人工批准区分开，`note.rule` 进一步分出 official 与 community 两类。
- 放宽任何一项条件都需要新的 ADR，不得在实现里悄悄扩大白名单。
