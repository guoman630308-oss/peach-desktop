# ADR-0051：label 可以挂在另一个 label 下面

- 状态：Accepted
- 日期：2026-09-24
- 关系：修订 [ADR-0049](0049-labels-belong-to-a-maker-without-becoming-one.md) 的「只有一层」，其余各条不变

## 背景

ADR-0049 只允许一层：label 挂片商，label 不能再挂 label。素人ホイホイ系的实际结构有三层：

- `妄想族` 是片商，官网 `/makers/` 把 `素人ホイホイ/妄想族` 列为旗下一家（maker 379，出实体盘）；
- `素人ホイホイ` 在 FANZA素人 上另开了十几个独立品牌：power（POW）、sweet！、Z（HOI）、LOVER、tower 等，
  各有各的番号前缀，性质和 Prestige 旗下的 ラグジュTV（LUXU）一样；
- 这些品牌的作品也会收进 `素人ホイホイ/妄想族` 的实体盘合集。

只有一层时，账本只能二选一：把 sweet！ 直接挂到妄想族，跳过素人ホイホイ；或者把素人ホイホイ
当成顶层片商，丢掉它和妄想族的关系。账本里两种错法都出现过：`素人ホイホイsweet！/妄想族`
直接挂在妄想族下面，`Amateur Hey-hey Power` 则没有任何归属。

用户 2026-09-24 的要求是新写一份 ADR，让三层都能在账本里记下来。

## 决策

`label_maker` 的表结构不变。一个 label 的上级可以是另一个 label。

- **不许成环**：装入脚本沿上级一路往上查，查回到自己就拒收，账本里已有的关系和本次复核表里
  同批的行都算进去。合并实体时 `merge_entity` 如果造出了环，就删掉合并目标自己的那一行上级：
  它吞掉的正是原来的顶层。
- **不限层数**：没有哪一家需要三层以上，但也不专门为此设上限。页面读取链条时有一道深度保护，
  防的是坏数据，不是业务规则。
- **同一张复核表可以一次建完整条链**：一个名字在账本里还没有实体，但在同一份表里既是 label
  又是上级，`--create-makers` 会先把它建出来，再写它自己的那一行。
- **作品详情列整条链**：「片商」一组从近到远，列出这部作品所属 label 的每一级上级。
  素人ホイホイpower 的作品显示「素人ホイホイ、妄想族」，ラグジュTV 的作品照旧只有「Prestige」。
- **资料页只链直接上级**：label 页在归属那一格只链上一级；上一级的页面再链它自己的上级，
  并照旧用「旗下」列出下一级。每一页只说相邻的两层，不把不同层级混在同一行里。

作品数仍然各算各的，任何一级都不把下级的作品算进自己名下。

## 后果

- 中间层没有自己作品时，和妄想族一样，是一条没有作品的 `studio` 实体。
- 名字里的 `/妄想族` 是妄想族官网给旗下厂商的写法，意思是「属于妄想族」。挂上一层关系之后，
  这层归属由 `label_maker` 表达。一个品牌主要以自己的名字在别处发行时（如 FANZA素人 上的
  `素人ホイホイsweet！`），规范名用它自己的名字，带 `/妄想族` 的写法降为别名，番号站按旧名
  照样查得到。只在妄想族名下出现的厂商（`ABC/妄想族`）不受影响。

## 修订：旗下都归片商（2026-09-24）

「各算各的」让妄想族这样作品全在旗下的片商显示 0 个视频，在厂牌索引页上也找不到。用户
当天的要求是「旗下的都归他」，和事务所处理艺人一样。本节取代上面那一句和 ADR-0049 的同名条款：

- **合计**：片商的范围是它自己加上 `label_maker` 往下的每一级。资料页的视频数、代表作、标签、
  同台艺人、照片墙，以及 `/api/items?studio=` 的作品列表都按这个范围算。判据只有一份，是
  `web_entity.scope_predicate` 的 `studio` 分支；作品列表那条因为循环导入另写了一遍同形的递归。
- **名册**：片商页旗下的 label 摆在筛选条下面，和事务所页的艺人同一个位置、同一套视图键。
  每格是厂牌的方形标识格，数字是那个 label 连同它自己下级的合计。头部只写「N 个视频 · M 个厂牌」。
- **索引页**：只列最上层的片商，按合计排序；有上级的 label 从片商页的名册进去。按名字搜索时
  所有厂牌照常列出，找 label 不必先知道它归谁。
- 首页那排厂牌是按作品随机抽的，这一节不涉及。
