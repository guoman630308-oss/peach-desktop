# ADR-0052：实体层证据充分即落库

- 状态：Accepted
- 日期：2026-09-24
- 修订：ADR-0040 第七条；AGENTS.md「AI 结果只产生候选」那一条

## 背景

字段层早已有免复核路径：空字段上来源一致的取值直接落（ADR-0018、ADR-0025）。实体层没有。
头像、厂牌官网、厂牌标识、厂牌归属、别名、改名，每一类的判据其实都写好了，住在一份份
命令行脚本里：先跑采集出复核 CSV，人看一遍，再带 `--apply --backup` 跑安装。这套流程在
维护者自己的机器上勉强能用，对别的用户则意味着扫完库之后厂牌页一片首字母，要补就得学会
十几条脚本的顺序。

用户原话：「其他真实用户使用 peach 的时候不要这么麻烦，我们就是要追求完全的无感落库，为什么
要重复验证这么多次？」

逐类核对之后，答案是：很多「复核」并没有在判断任何东西。判据已经由代码给出结论，人看的那一遍
只是确认代码确实这么判了，同一个结论被验证了两次。真正需要人的只有两种：判据本身说「分不开」
的（`weak`、多候选、来源冲突），以及写下去就撤不回来的（合并、改规范名）。

打包出去的 EXE 不带 `scripts/`，所以判据还住在脚本里的，普通用户那边等于不存在。

## 盘点

| 类别 | 确定性证据（自动落） | 要人判（进复核） | 本 ADR 后 |
| --- | --- | --- | --- |
| 女优头像 | 图库按整条名字链只命中一张且过 `acceptable_avatar`；否则单人作品封面上脸最宽的一张 | 图库命中多张 | 已随刮削自动补（ADR-0040） |
| 厂牌官网 | `studio_sites.site_verdict` 判 `ok`：页面自述厂牌名且是成人站，或域名由厂牌名推出且是成人站，或在 `CONFIRMED_SITES` | `weak`（同名无关公司分不开）、发行平台 | 随刮削自动补 |
| 厂牌标识 | `studio_icons` 判 `ok`／`字标补白`，人像闸生效且落盘前再过一次，只换更大的 | 仍是字标、只有小图标、平台通用图标、人像 | 随刮削自动补 |
| 厂牌归属 | 官方名录或官网自述「某某旗下」 | 两处来源说法不一 | 判据可定，接入待后续 |
| 别名 | `link_performer_name_variants` 的三条（同片同人数、只差一个名字、只有一侧解析得到实体） | 写法被另一条实体占用、统称已变 | 判据可定，接入待后续 |
| 合并／改规范名 | 写法变体逐字相等、番号前缀唯一命中 | 撞上两家以上 | 仍需授权：`merge_entity` 撤不回 |

## 决策

**一、判据由代码给出结论、同样输入给同样输出的，直接写 ledger，不产生候选。** 这取代「AI 与
刮削结果只能作为候选、只有用户复核后才 `approved`」那条一刀切的规则。LLM 输出、打分阈值、
要看画面才能判的，仍然只进候选。

**二、每条自动写入都能按来源整批撤回。** 写入记三样：归属串 `source`（`auto:<后继名>`）、
判词 `verdict`（判据的名字就是置信度：`ok`、`字标补白`）、批次 `batch`（`<source>@<任务行 id>`）。
链接记在 `entity_link.metadata_json`，标识记在旁边的 `.provenance.json`。
`scripts/revert_auto_landing.py --source … [--batch …]` 按它们撤回，默认 dry-run，`--apply`
要 `--backup`。写下去撤不回的一类（合并、改规范名）不属于自动落库，即使判据确定。

**三、只填空，不覆盖人的判断。** 厂牌盘上已有任何一张标识就整条跳过；已有官网或目录链接就
不另找官网，直接按它取图；标识只换更大的；人装的、人挑的一律不碰。所以撤回就是删除：自动写下的就是那一格的全部。

**四、门槛自己失效时不落。** 人像闸取不到模型时一张标识都不装，摘要里写明原因；官网试不通
记 `未取得`。宁可留空，也不在没有闸的情况下写。

**五、冲突项才进复核页。** `weak`、多候选、来源冲突照旧写进复核产物等人。自动路径跑完之后，
复核页上剩下的就只该是这些。

**六、接在处理任务后面，普通用户不用跑脚本。** 实体层的自动落库一律做成 ADR-0040 的后继：
`process_library` 结算时按实体 id 水位声明，写账本的走串行通道，处理器幂等。判据从 `scripts/`
搬进 `src/peach/`（`studio_sites`、`studio_icons`），命令行和后继共用同一份，脚本只剩参数解析
和复核件读写。

**七、修订 ADR-0040 第七条。** 厂牌不再只登记缺口：新登记且盘上没有图的厂牌派一条
`studio-mark` 后继，先按第一条的判据补官网（没有官网链接时），再按官网取标识。
`entity-avatar` 后继只管女优。

## 后果

- 扫描采集出新厂牌之后，官网与标识在同一轮后继里补上；活动页上每家一行，写明装了什么或
  为什么没装（`官网待人确认`、`仍是字标`、`人像闸未生效…`）。
- 判据错了一批，撤回是一条命令，不是逐条找。
- `AGENTS.md` 与 `peach-ledger-write` 的候选规则改成本 ADR 的口径。
- 头像沿用 `avatar_picker` 的边车，记着出处与 `policy_version`，没有批次号；换回旧图走挑图
  弹层（候选缓存保留全部历史）。头像要整批撤回时再补批次。

## 未决

厂牌归属与别名的判据已经确定，接进后继时各自按第二条补上撤回路径。合并与改规范名要先有
「合并前快照、可原样还原」的能力，才谈得上自动。
