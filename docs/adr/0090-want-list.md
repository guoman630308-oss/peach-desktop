# ADR-0090：「想要」清单单独成表，入库按番号自动对账

- 状态：Accepted
- 日期：2026-10-01
- 相关：ADR-0040、ADR-0052、ADR-0083、ADR-0089

## 背景

「关注女优」只表达持续知道她的作品，「这部我想要」是另一种意愿（SakuraMedia 把两者分开）。想要的对象
有三种形状：Feed 番号壳、关注条目、用户手输的库外番号，它们都还不在库里。「寻找更好版本」的
`asset_quality_goal` 主键含 `asset_id`，只能挂在已入库的作品上，装不下这三种。

## 决策

**一、`want_item` 单独成表**（迁移 0042）。`code` 存登记时的写法，`code_key` 存
`normalise_code_key` 的结果，番号键与关注条目各有部分唯一索引；行上快照标题、封面、发行日、厂牌与
女优。已在库的番号拒绝登记。想要与屏蔽互斥：忽略会撤掉想要，点想要会解除忽略。

**二、状态只有待找、暂时放弃、已入库三种，未发售按发行日现算。** 发售 90 天内的新片一直算待找，查不到
也不计数；老片查满 3 次无果标「暂时放弃」，可手动重新查找；发行日缺失按老片算。查找结果由下载模块经
`wants.record_search` 记入。

**三、入库按番号自动对账，按 ADR-0052 直接落库。** 全量扫描与 `scan.ingest_path` 登记的新文件番号命中
就标已入库，关注条目保存进账本时也对账；来源 `auto:want-acquired`，批次 `auto:want-acquired@<时刻>`，
`revert_auto_landing.py` 可整批撤回回到待找。`acquired_asset_id` 不挂外键：扫描连接不开外键约束。

**四、清单是关注管理页的「想要」页签**（`/follow-manage?tab=wants`）。想要的两个来源 Feed 与关注都在
这一页管理；旧壳路由表冻结，不另开页面。加入时取资料任务把封面存一份本地。

## 理由

- 三种来源共用一张以番号为键的表，下载、对账与提醒都只认番号。
- 未发售是时间推出来的，存成状态就得有人按时改它。

## 后果

- 文件名里解析不出番号、或番号要等补资料后才写进 `asset.code` 的文件，入库时对不上，条目要手动移除。
- 想要按全局记，不分 profile。
- 撤销「忽略」只恢复忽略状态，不恢复被撤掉的想要。
- 书签提醒与外部清单导入不做，理由见 ADR-0092。
