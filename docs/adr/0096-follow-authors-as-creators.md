# ADR-0096：关注作者落成创作者实体

状态：已接受。最后复核：2026-10-08。
关系：修订 [ADR-0019](0019-site-follow-connectors-and-variant-grouping.md) 的作者别名一节；按 [ADR-0052](0052-entity-results-land-when-evidence-is-sufficient.md) 直接落库；遵守 [ADR-0095](0095-entity-classification.md) 的同名规则；后继派发沿用 [ADR-0040](0040-tasks-declare-followups-at-the-end.md)。

## 背景

关注页把同一个人在几个站上的来源归成一组，但这组只存在于关注页：没有资料页，名册在线档点开只能回关注页筛选。这些作者通常有正版发布渠道（FANBOX、Patreon、SubscribeStar 等）和社媒账号，来源数据里已经有这些信息，却没有写进账本。

## 决策

关注里每一组还没建档的作者落成一条 `creator` 实体，绑上名下的 `follow_source`，资料页与本地创作者共用同一页。

- **时机**：关注检查结算时，如果有要建档或并入的作者，就声明后继 `follow-creator`；后继在一个写事务里完成计划与写入，走写账本的串行通道。判据都是确定的，不联网。
- **建谁**：没绑实体、作者键是名字的每一组。名字取关注页的写法，经过 `canonicalize_entity_name('creator')`；被平台名、结构目录或转载站规则挡住的整组跳过。
- **只列不建**：账本里已有同名或同别名的创作者，或几组归一成同一个名字。按 ADR-0095，姓名相同不能自动关联。本地那位的资料页提示「关注里有同名作者」，用户按「是同一个人」后才绑定，写入归属 `user:follow-creator`；名册在线档的这一格读数带「待确认」，点开去那位的资料页。
- **并入**：新来源和已建档实体名下的来源，在绑定前属于同一个名字键时直接绑过去。这是关注页原有的分组，不是新的同名推断。
- **链接**：只在绑定时写一次，用户删掉的不会在下一轮重新出现。正版渠道记 `official`，社媒记 `social`。来源包括三类：官方来源自己的地址；归档站上已核实形状的原站账号（FANBOX 数字 id 对应 pixiv 用户，Patreon 用户 id，OnlyFans 用户名）；名片里可信的条目（F95 开楼正文全收，booru 只收手柄等于作者名的）。归档站和聚合站本身不登记为链接，`follow_source` 的绑定已经记录了它们。
- **撤回**：自动写入的每条记录都带 `auto:follow-creator` 与批次号。`scripts/revert_auto_landing.py --source auto:follow-creator` 会解绑来源，删除这一批的链接与别名；实体只有在没有其他引用时才删除。用户确认的绑定不在自动撤回范围内。
- 绑定后关注页的作者键变为 `entity:<id>`；别名表仍按名字键记录，归组时按名字键找到对应实体。

## 后果

- 名册「创作者」档只列有入库作品的实体，纯在线作者仍在「在线」档；两档合并另行处理。
- 绑定后再删除别名，已绑定的来源不会拆开。
- Gumroad、Fantia 的归档 id 形状未核实，暂不还原原站账号。已有 F95 来源不会按新的名片白名单重新解析。
- 资料页头像在读取时回退到关注那边的头像，不写盘。
- 创作者资料页提供「在线」视图（`?media=online`），展示已绑定来源的关注更新，本地作品使用「视频」「照片」视图。本地没有作品时默认打开在线内容。筛选、视频与图片两档和照片墙沿用关注页；来源与标签使用 `/api/follow` 的 `author_facets`，只统计当前作者。关闭在线详情后保留资料页筛选、页码与滚动。
- 自选头像可读取社媒头像、在线作品封面和正文图片，框选、整图使用和安装沿用头像选择器。候选只来自当前实体绑定且未隐藏的内容；自动社媒解析覆盖 X、Patreon、pixiv 与 FANBOX，其他图片可由用户提供地址。取图请求按来源主机限制凭据、大小与时限。
