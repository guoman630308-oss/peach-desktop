# ADR-0086：FC2 出演者的 `Xちゃん` 与另一家的 `X` 算两家一致

- 状态：Accepted
- 日期：2026-10-01
- 相关：ADR-0025、ADR-0038、ADR-0052、ADR-0072、ADR-0079

## 背景

FC2 素人作品的出演者栏，javdb 常写 `みおちゃん`，fc2ppvdb 与 fc2cmadb 写 `みお`。ADR-0079 把
带敬称的写法当成剪不出艺名的称呼，剔掉后只剩两字短名时整行交人：只凭一个短名认人，ADR-0072 说过
会命中别人。

## 决策

**一、FC2 番号的 performers，满足下列全部条件的候选按 `X` 参与比对：**

1. 整条候选只有一位，写法是 `X` 加 `ちゃん`；
2. 同一行另有一家候选剪出的艺名整条就是 `X`；
3. `X` 本身剪得出艺名（`stage_name(X) == X`）；
4. 账本里 `X` 解析不到实体，或解析到的就是以 `X` 为规范名的那一条（`_names_only_itself`）。

折过的候选与另一家照常比对。一致时 `agreed_sources` 按两家计，落库署名仍按字段优先级链取：
fc2cmadb、fc2ppvdb 排在 javdb 前面。折过的候选只留名字，javdb 演员页的编号不跟着落。

**二、规则名与留痕。** 落库 note 的 `rule` 写 `adr-0086-fc2-honorific-<n>-agreed-sources`，
`honorific_agreed` 记被折的来源与原写法。

**三、不适用的情况照旧交人或归 ADR-0079 判：** 只有一家写 `みおちゃん` 的行；敬称前的名字只是
另一家多人名单里的一位；`X` 是别人的别名（`夏希` 解析到 `夏希南`）；非 FC2 番号；`さん` 等其余敬称。

## 理由

- 两家独立给出同一个名字，敬称是 javdb 抄了卖家标题里的称呼，并不构成另一种说法。按
  ADR-0052，证据足的应该自动落。
- ADR-0072 担心的是「凭一个短名去认人」。条件 2 要求另一家给出同一个名字，条件 4 挡住短名落到
  别人名下；剩下的风险就是不同卖家的同名素人共用一条实体，账本在这之前已经如此。
- 规则名单独一条，出错时能从 `review_decision.note` 按它整批认出来。

## 被否决的方案

- **在 `stage_name` 里剪掉 `ちゃん`。** 这个函数还供企划名义判断与别名登记使用。
  `超バドミントン部あかりちゃん` 剪完是 `超バドミントン部あかり`，描述词表认不出来，就会变成艺名。
- **放宽短单名门槛，让 javdb 那条照旧作为描述性称呼剔掉。** 这样落库记的是单一来源，
  `descriptive_dropped` 里写着 javdb，与「两家一致」这个事实相反。

## 后果

- 不同卖家的 `みお` 继续共用一条实体。要分开，得靠卖家或站上编号另建身份，不在本条范围内。
