# ADR-0073：实体的公开事实随仓库分发，导入只给已有实体填空

- 状态：Accepted；分发位置由 ADR-0111 修订；第三、四条与「触发时机」由 [ADR-0075](0075-seed-pack-refreshes-its-own-rows-and-lands-after-scans.md) 修订
- 日期：2026-09-25
- 修订：ADR-0024 第四条（共享清单的维护者结论不自动升级本机 ledger 真相）
- 关系：ADR-0024 第五条（新建空库不因此获得另一用户的实体）继续成立；ADR-0026 的法人／自然人分界；ADR-0052 的归属与撤回契约

## 背景

公开站点的规范身份、别名、编号与文字资料可按来源核对。复用经审查的事实包可以减少重复请求；从个人账本导出的实体组合仍属于私有记录，分发边界见 ADR-0111。

用户 2026-09-25 问：「女优图像链接、对应 minnano-av json 数据社媒信息、厂商对应 logo 链接等等这些
比较固定的不行吗」。答案分三层：找法（解析器、限流、判据）本来就在代码里；厂牌标识字节 ADR-0026
已经随仓库走；中间这层「查到的事实」此前只住在维护者的账本里，别的用户拿不到。

ADR-0024 第四条说共享清单的维护者结论不自动升级本机真相，写下它时想的是图片地址与身份变化那类
会过期、要人确认的东西。事实层不同：别名、站上编号、官网地址来源确定、可重新核对、能整批撤回，
ADR-0052 已经允许这类结论由代码直接落库。本 ADR 把第四条改成：**带来源与批次、只填空、可整批撤回的
事实可以随仓库分发并直接导入；图片地址与任何要看画面才能判的仍不自动升级。**

## 决策

**一、分发的是文字事实，按实体归拢。** `resources/seed/entities.json` 一份，`scripts/seed_pack.py export`
从本机账本只读生成。每位女优、每家厂牌与事务所一条：规范名、别名（带原来源串）、站上编号、官网与
社媒链接、女优资料表的各列与标签、所属事务所。不导 `entity.metadata_json`（本机快照路径、复核项）、
资料的 `raw_json`（刮削残片）、链接的 `evidence` 文本、`is_sensitive` 的链接、目录页与来源引用类链接、
Stash 的编号（另一份数据库的行号）。只有名字的实体不进包。

**二、为什么文字事实可以随仓库走而肖像不能。** ADR-0026 把分界画在法人与自然人之间，针对的是图像：
分发肖像等于替代用户去取得一个人的样子。艺名、出道年份、事务所与本人公开的社媒地址是这个人以艺名
公开活动的事实，各站已公开索引，包里的每一条都写着它来自哪一站，读到的人拿着来源能自己核对。资料表里
的生日、三围、血型、出身地也是站上公开的资料页内容，但它们更接近个人数据；本 ADR 收录它们，因为
账本里的资料页功能就是这几列，收一半等于没收。**推不推这份包到公开仓库由用户看着字段名决定**，导出器
与导入器合入不等于数据包已发布，数据包单独一个提交。

**三、导入只给已有实体填空，不造实体（ADR-0024 第五条）。** 包里一条按规范名逐字、任一写法唯一命中、
站上编号唯一命中的顺序对本机实体，对上两位或一位都对不上的都跳过并计数。对上的那位：女优别名走
`performer_alias_followup.land`（ADR-0055 的不收、已有、被占用三道判据），厂牌与事务所别名只查同类
实体里是否有人用着；编号只在这个编号没人登记、这位在这家来源下也没有编号时写；链接按现主机归一后
`INSERT OR IGNORE`；资料只给没有资料行的写；所属事务所只在本机已有这家事务所、这位又没有归属时写，
不造事务所。本机后继刚刮的资料比种子新，`write_profile` 的整行替换在这里不用。

**四、归属与撤回照 ADR-0052 第二条。** 归属串 `auto:seed`，批次 `auto:seed@<版本>`。别名、资料、
所属事务所的 `source` 列直接存批次号，编号与链接在 `metadata_json` 里记 `source` 与 `batch`。
`scripts/revert_auto_landing.py --source auto:seed [--batch …]` 五张表一起撤，本 ADR 给它补上
`entity_membership`。种子自己写下的行不再被导出，两台机器互导不会滚雪球。

**五、版本与确定性。** 版本号由 `--version` 显式给，默认当天日期；不用运行时刻。输出按种类与归一名
排序、键有序，同一账本同一版本两次导出逐字节一致，内容没变就不改文件。

**六、导入逻辑在 `src/peach/seed_pack.py`，脚本只做命令行。** 打包的 EXE 不带 `scripts/`
（ADR-0052 第六条）。`import` 默认 dry-run（在只读账本的内存副本上跑一遍报计数），`--apply` 要 `--backup`。

## 不包含什么

- 头像地址与摘要。没有表接它，接进补头像后继要改 ADR-0040 的路径；见「未决」。
- 厂牌与事务所标识。ADR-0026 已经分发字节本身，再带一份地址是第二条通道。
- 任何图像字节、本机路径、复核 CSV 的内容、`asset` 层的任何数据。

## 未决

- 导入的触发时机。v1 只有命令行；接在首次设置或处理任务结算后面时，按 ADR-0040 的后继形态做，
  并在活动页写明补了什么。
- 头像的来源指针（`source_url` 与 sha256）要不要进包，取决于补头像后继能否消费它。
- 包里的资料列是否收窄（只留艺名、出道年份、事务所）由用户在决定推送数据包时定。

## 后果

- 新机器扫完库，账本里对得上的人和厂牌在下一次导入后就有别名、编号、链接与资料，不必各自把几千个
  请求再打一遍；对不上的什么都不发生。
- 判据错了一批，撤回是一条命令。
- 仓库多一份 JSON，体积以 MB 计；数据包更新是显式的一次导出与提交，不随每次采集变动。
