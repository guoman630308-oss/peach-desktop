# ADR-0013：目录名只作为创作者候选证据

- 状态：Accepted
- 日期：2026-08-15

## 背景

旧导入器曾把目录组件直接写入 `asset.creator`，再由规范实体迁移以
`source='legacy:asset'`、`confidence=0.8` 投影为创作者关系。实际目录同时包含精心整理的
创作者目录、集合目录、发布站目录和为流量取的标题。例如「足交仙人」是集合名，文件水印和
文件名共同指向 `suzuq`；`B:\MVP\捅主任\TokyoDolls` 也不能因为上层目录就归给捅主任。

## 决策

- 新扫描器不从目录自动建立创作者真相。
- 目录组件只生成候选；持久归属至少需要水印、番号、发行元数据、公开链接或用户确认之一。
- 用户确认和文件级证据使用独立 `source`、置信度和证据摘要，不覆盖成模糊的 `legacy:asset`。
- 批量纠正只处理边界明确的路径子树；其余历史关系逐项导出 CSV 复核，不按目录整体重写。
- 兼容字段 `asset.creator` 必须由规范关系重新投影，不能和 `asset_entity` 分叉。

## 被否决的方案

- 认为所有 `创作者\名字` 或同名目录都天然可靠。
- 因发现一处错误而清空同名创作者的全部作品。
- 用人脸识别替代水印、番号和发行来源证据。

## 后果

旧数据需要一次较大的复核队列，但不会继续扩大。自动化速度略慢于目录直写，换来可解释、
可撤销且不会把集合名传播成创作者级标签的身份判定流程。
