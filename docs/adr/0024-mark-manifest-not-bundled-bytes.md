# ADR-0024：来源清单、可更新解析器与本地图像缓存

- 状态：Proposed（方案已修订，运行时尚未实施）
- 日期：2026-09-05
- 关系：ADR-0023 的陌生用户安装流程；ADR-0018 的元数据候选；ADR-0019 的来源凭据；ADR-0017 的本机数据边界。
- 证据与逐脚本审计：[来源采集](../SOURCING.md)；来源细节见 [SOURCING](../SOURCING.md)，依赖决策见 [REUSE](../REUSE.md)。

## 目标与边界

不同用户在各自 Windows 或 macOS 电脑上，使用自己的馆藏、网络和可选站点会话，能够通过图形界面完成来源配置、取图、复核与失败恢复。Peach 仍是单用户应用，不引入多账号服务。

发行版及项目维护的云端只分发来源清单和解析器，不分发第三方图片。清单不能消除原站的地域限制、认证、删图或限流。承诺可重复执行、可解释失败和保留已取得图片；不承诺任意网络下取得同一数量图片，也不承诺原站删除后还能取得同一字节。

标识、头像和封面进入本方案；本机媒体抽帧与照片缩略图继续由已有派生管线生成。公开清单不含本机 ledger ID、用户路径、Cookie、代理凭据或临时签名地址。

## 产物边界

`posters/` 与 `photo-thumbs/` 派生自用户媒体，不进入公开来源清单；`link-marks/` 是按主机生成的运行缓存。`logos/`、`avatars/`、`covers/` 只有在来源、许可与 provenance 可核对时才进入对应分发流程。实际文件清单、数量和占用保存在部署数据根。

## 决策

采用「来源定位 → 按需解析 → 有界下载 → 候选复核 → 本地安装」的单一流程。GUI、CLI 和批处理调用同一个应用服务，不各自实现抓取逻辑。

1. 来源清单保存稳定身份、来源主页、解析器及用途；已核验直链只是可失效的快速路径。
2. 解析器从原站公开数据或用户有权访问的会话重新取得地址。Instagram 等签名地址允许进入本地解析缓存，随过期刷新。
3. 下载缓存按原始字节 SHA-256 寻址；转换产物单独寻址。界面读取本地已安装图片，不依赖每次打开页面时第三方 CDN 可用。
4. 来源失败保留最后成功图。图片变化、身份变化与用户明确选择的覆盖都通过现有候选复核契约；共享清单的维护者结论不自动升级本机 ledger 真相。
5. 只抓本机需要的实体与番号。新建空库不因此获得另一用户的实体、成员关系或整套馆藏目录。

### 为什么分发清单而不是字节

- **仓库是公开的。** 这批图里有第三方商标、真人肖像和成人作品封面。提交进公开仓库等于由这个仓库对外再分发，和用户自己去原站取回来是两件事。
- **体积。** 1.45 GB 里 96% 是封面。Git 存二进制不做 delta，更新一张就多留一份全量。
- **图会变。** 事务所改版、艺人换头像、厂牌重做标识；打包进去的那一份从写进仓库那天起就开始过期，而清单里的摘要恰好能说出「它变了」。
- **平台政策。** 成人封面进公开仓库有被下架的实际风险，且下架会连带整个仓库。

云端主机替所有用户抓同一批图再发出去，是同一件事换了个位置：字节仍由这里对外再分发，只是从 Git 换成 HTTP。云端能做而本地做不好的只有持续复查「地址还活着吗、图换了吗」，那是清单的工作，不是字节的工作。

## 质量目标与网络路线分别配置

高清是来源及质量选择，代理是到达来源的网络路线，两者不绑定。高清图可能可以直连；低清元数据站也可能在某个地区不可达。

| 质量目标 | 行为 | 请求预算 |
| --- | --- | --- |
| 标准（新用户默认） | 来源归属和用途通过后，达到现有展示质量线即停止；原站给高清也直接保留 | 优先缓存与低成本来源，缺图才解析 |
| 最高可得画质（维护者使用方式） | 汇总已验证候选，比较真实尺寸、完整性和用途；保留已有高质量图 | 在用户设定的请求、流量和时间预算内继续比较；达到预算标记未穷尽 |

「最高可得」不表示遍历互联网或固定站点永远最好。封面继续复用 Javinizer-Go 快照、DMM、Prestige、MGS 与已核实历史来源；保留现有按番号和发行证据分流、Range 测尺寸、仅升级合格图片的能力。标准模式的质量线须按标识、头像、封面分别设定，不能把小圆标的短边 360 阈值套给封面。

每个来源配置「不使用应用代理／跟随环境／指定代理」，作用于运行 Peach 的主机，而非打开网页的手机。明确设置的代理由 HTTPX、curl_cffi 和外部工具各自适配到同一策略，子进程不能靠碰巧继承开发者环境才可用。跟随环境不保证发现 Windows/macOS 的系统代理或 PAC；仅在实现并通过平台测试后提供对应选项。

连通性测试分别检测元数据页与图片 CDN，报告 DNS、TLS、超时、认证、限流和内容不匹配。`trust_env=False` 仅排除应用环境代理，不能排除 TUN、路由器或上游网络。无法观察的出口标「未观测」，不能报告物理直连成功。

仅在相关来源不可达时显示可操作提示：「此高清来源当前无法连接；所在网络可能需要代理。测试连接、配置代理，或继续使用已取得图片。」不把所有超时解释为需要代理，不切换系统代理或给无关站点改路由。DUGA 的「代理店应用 ID」是接口申请条件，与网络代理无关。

## GUI 配置与会话

复用关注管理的凭据表单、`CREDENTIAL_GUIDE`、`CredentialStore`、保存与撤销接口，扩展成来源配置页。现有表单已经支持粘贴字段；Instagram、FC2、元数据工具和网络设置的统一接入属于待实施内容。

1. 首次安装展示来源能力、标准／最高可得画质、预计范围与可选登录条件；无需先填 Cookie 才能开始公开来源。
2. 每个需要登录的来源提供「打开官方登录页」「粘贴 Cookie」「导入 Cookie 文件」「验证连接」「撤销」。文件导入先复用标准库 `MozillaCookieJar`，限制站点域名、大小和格式，禁止执行上传内容。
3. 浏览器导入作为可选便利入口：由用户选择浏览器和 profile，调用已验证的成熟库。网页自身不能读取另一个域的 Cookie；远程浏览器也不能直接导入其本机浏览器数据库。平台解密或文件锁失败时提供粘贴／文件导入，不要求用户关闭浏览器安全保护。
4. 保存、有效、过期、需验证、已撤销是不同状态。保存成功不能冒充登录有效；验证只做目标来源的一次有界请求，状态查询不回传凭据值。
5. 会话只在运行 Peach 的本机保存，按来源隔离，不进入清单、Git、ledger、诊断导出或默认跨机同步。Cookie 域与路径保留，跨站重定向不转发原站凭据；CDN 取图缺省不携带账号 Cookie。
6. 需要验证码或二次验证时暂停该来源，用户在官方页面完成后恢复。会话换出口可能失效，带凭据任务不能自动在多个出口之间轮换。

GUI、CLI 共用配置、凭据验证与任务状态。只上传 Netscape Cookie 文本，不导入不可信 pickle 会话文件；Instaloader 原生会话的生成和读取由本机受控适配器负责。

## 复用路径

| 能力 | 正式基础或实施候选 | Peach 保留的职责 |
| --- | --- | --- |
| 番号元数据 | 已有 Javinizer-Go v1.5.1 单来源 JSON 适配器 | 发行身份、字段来源、候选与复核；不接管其 organizer |
| 官网与名录 | 已有 `Site`、`HttpxTransport`、站点解析模块 | 身份映射、用途、缓存隔离与来源健康 |
| 图片字节与派生 | 已有 Pillow、`AvatarCandidateCache`、`LogoCandidateCache` | 原图与转换契约、质量、候选与安装 |
| Instagram 头像 | 优先验证 Instaloader 4.15.3（MIT）；gallery-dl 的头像提取器作为对照 | 目标账号归属、本站会话、限流、结果标准化 |
| 浏览器 Cookie 导入 | Instaloader 官方支持的 browser_cookie3 为候选 | 用户选择、域限制、存储和平台失败回退 |
| 任务与进度 | 已有 `BackgroundJob`、APScheduler、来源健康结果 | 持久断点、用户取消、预算和 GUI 状态 |

候选依赖必须通过实际账号、Python 3.12+、Windows/macOS 与桌面包的 POC 才进入运行时。记录许可证、固定版本、依赖体积、失败状态和首个消费者；本 ADR 不预装依赖，不把库的功能说明当成跨账号成功证据。

Instagram 按目标账号取得 `profile_pic_url`，核对来源账号 ID／handle，再下载其返回的完整地址。不改写签名参数，不从整个页面取第一个头像字段。浏览器补充路径只使用目标资料页实际提供的图像，不把观看者、推荐账号或通用图标当成目标。

`agency-avatars.json` 作为本机迁移输入保留；实体名称映射、handle 和原地址只能产生待核验来源记录。过期地址需重新解析，不能据此判定账号没有头像。公共清单保存账号定位，临时地址和最近成功摘要留在本机。

## 清单与缓存契约

公共清单分为 `data/marks/manifest.jsonl` 与按番号索引的 `covers.jsonl`，UTF-8、LF、稳定键排序。清单记录含 schema version，拒绝不认识的主版本；schema 不允许嵌入可执行代码。

| 字段 | 含义 |
| --- | --- |
| `key` | 清单分配且不随名称变化的 ID，加展示用途；不使用本机 ledger ID |
| `entity_kind`、`display_name`、`external_refs` | 类别、显示名与来源身份；来源主页／来源 ID 映射本机实体，冲突留复核 |
| `slot` | icon、logo、avatar 或 cover；不同位置分别选图 |
| `source_page`、`resolver`、`resolver_version` | 可以重新发现资源的来源页与固定适配器版本 |
| `access` | public 或 user_session；声明需要的站点会话，不保存凭据 |
| `verified_asset` | 可选的公开直链、原图 SHA-256、字节数、实测尺寸、格式及核验时间 |
| `transform` | 版本化的格式、补白、裁切等规则与参数；安装端根据本机映射生成安全路径 |
| `evidence` | 可公开的归属证据与人工核验记录；不是本机 approved 状态 |

原图 `raw_sha256`、候选 `candidate_sha256`、安装 `installed_sha256` 分开记录。固定转换工具和参数后，才可声明安装字节可重复；跨版本转换不得沿用旧摘要。JPEG 扩展名不决定真实格式，尺寸必须解码读取。

来源 URL 相同但原图摘要变化时，记 `source_changed` 并保存候选，不自动更新固定清单的预期摘要。最新图片刷新与固定快照校验是两种操作；用户明确选择的图片默认锁定。

本地解析缓存包含来源 ID、会话作用域、解析器版本、临时地址、解析时间、最近成功原图和下次可请求时间。认证缓存不按 URL 单独混用；限流预算按来源／会话及已知出口共享，同一 provider 的 CDN 分片域名不能绕开来源预算。

下载器只接受允许的 HTTPS 来源，重定向逐跳检查目标与凭据边界，限制响应和解码尺寸，拒绝任意本机路径及路径穿越。完整性通过后临时文件原子替换；真实安装复用 `.ct`、provenance 和现有 `/logo`、头像、封面路径契约。

## 请求效率与长期运行

- 本机原图缓存优先，重复 URL 合并请求，重复字节合并存储，同一主页一次解析产出多个候选。
- 普通来源建议初始全局并发 4、每来源 1～2；Instagram 同一会话串行，沿用上游限流器。以实际失败率调整，不能以这些初始值承诺安全速率。
- 支持时发送 ETag／Last-Modified；不支持时按来源 TTL 刷新。健康复查时间进入独立记录，内容清单只为身份、资源或策略变化更新，避免无变化 PR。
- 最高可得画质保留 Range 探测；服务器忽略 Range 返回 200 时仍限制读取字节并关闭响应。能复用探测结果时不重复下载同一资源，原图不因一次派生转换丢弃。
- GET 的传输错误和暂时性 5xx 有限退避；429 尊重 `Retry-After` 并持久冷却。无头部时按来源策略冷却；不得反复换出口继续打。
- 401、登录页与验证页暂停来源；403 分类为拒绝／可能过期等可确认状态，不统一解释为限流。签名失效或资源 404 可重新解析一次，仍失败则保留旧图并报告未取得。
- 断点记录已完成条目、候选、请求／流量预算和冷却状态。程序重启不清零预算，不自动重放已完成安装或待用户复核的写入。

云端只能证明自己的网络和时刻下可用。它生成可复核的清单变更和健康报告，不持有用户会话、不为所有用户代抓分发图片，也不替用户决定真实 ledger。

## 实施与验收

按依赖顺序交付，每步分开验证；方案完成不代表功能上线。

1. 核对已有边车和抓取日志：日志只作线索，能够按内容摘要及转换规则关联的才补核实来源；其它进入复核件。禁止仅凭同名／同番号把某条历史 URL 宣称为现有文件的已验证来源。
2. 来源定位与下载缓存服务：复用当前模块，统一错误、原图摘要、转换和安全安装契约；先接普通来源与 Javinizer-Go，再接最高可得画质。
3. 来源配置 GUI：公开来源开箱可用；Cookie 粘贴／文本文件导入、保存／验证／撤销、按来源网络策略与 CDN 测试共用现有 API 和凭据仓库。
4. Instagram 小样本 POC：至少 Bambi、LINX、一个普通个人账号、一个无头像或失效账号；两个独立用户会话；只验证有权访问的内容。记录实际原图尺寸、身份、请求数、耗时和失败原因，稳定达到范围内目标后再引入适配器。
5. 清单导出与首次运行：标识、头像、封面分别按本机需求预览数量和预算，批准后执行；无来源或不可达的条目不妨碍其它条目。

验收矩阵覆盖 Windows 与 macOS、干净数据目录、两个独立用户、未登录／已登录、应用直连／指定代理、标准／最高可得画质。每个组合记录版本、缓存状态、来源命中和图片 CDN 结果，不能用一台机器或离线 fixture 冒充全部通过。

- 同一冻结输入导出逐字节一致；实体改名或本机 ID 不同仍映射到正确来源，名称冲突进入复核。
- 冷启动记录请求、字节和耗时；相同输入二次运行不重复下载完整图片。
- 原站换图、URL 过期、限流、缺凭据、断网和取消后均可恢复，已有合格图不消失。
- 固定快照摘要不符不能安装；转换前后摘要各自正确；更大但身份错误或用途错误的图不能覆盖。

复用表里「番号元数据」那一行与实施顺序第 2 条把 Javinizer-Go 列为正式基础，被 ADR-0044 取代：番号元数据由 Peach 自写的官方站解析器与 amane 桥承担，其旧快照只作封面层的离线证据。 <!-- copy-lint-disable-line -->
- Cookie 域、重定向、日志脱敏、撤销、缓存作用域、非法 target 和解码上限有隔离测试。
- GUI 保存不等于有效，连接失败时能继续公开来源或已有图片；桌面和 390×844 视口都有可执行入口。
- 仓库里不出现任何新的图片二进制，由 `tests/test_repo_hygiene.py` 的一条守卫拦住：清单进 Git，字节不进。
- 测试通过项目单一入口；涉及共享网络、凭据、构建和多域实现时跑 full；文档修订按相关静态门槛验收。

## 非目标

不新建通用爬虫框架，不同时集成多套承担同一正式职责的下载器，不克隆别人的会话与图库，不绕过机器人验证。原站永久删除且本机没有缓存的图片记未取得；需要永久字节可用性时必须另行取得可分发资源与授权，本方案不作隐含承诺。
