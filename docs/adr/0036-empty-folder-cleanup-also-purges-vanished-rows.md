# ADR-0036：空文件夹清理连文件已消失的账本行一起删

- 状态：Superseded by ADR-0080（逐条 `stat` 定罪、来源先判在线、回收站的行一起算仍有效）
- 日期：2026-09-16

## 背景

用户在网盘客户端里删掉一个目录，本机看到的是两样东西：挂载盘上留下的空壳目录，和账本里
一批指向不存在文件的行。这两样东西此前由两条互不相干的路径处理，而且都漏掉了一部分：

- 空目录只有数据管理页上一对手动按钮（`/api/data-cleanup/empty-folders`），不在
  `task_runs.TASK_LABELS` 里，任务中心看不到它跑过没有。

这 469 行不是静止的。115 那一轮抽帧报的 73 条 `broken_source` 里有 72 条是它们，每次重跑
再失败一遍。那一轮的直接原因由 `jobs.ACTIVE_ASSET_SQL` 修掉了（长跑批处理不再领回收站的
行），但行本身还留在库里，用户也没有一个入口能把它们清掉。

## 决策

**一、空目录清理同时删掉这个来源上文件已经消失的账本行。** 判据复用资源对账那一套目录
枚举（`web_resource_sync.vanished_asset_rows`，内部就是 `_missing_resource_ids`），与对账
的区别只有一条：回收站的行也算。删除走 `purge_assets` 这唯一一条物理删除实现。

**二、来源必须先判在线。** 盘没挂上时目录读不到，每一条都会被判成文件没了。`online` 为假
的来源整个跳过，和空目录那一步共用同一个判定。

**三、检查（`dry_run`）只报数不删。** 界面上先出「N 个空文件夹、N 条文件已不在盘上的记录」，
删除仍走共享确认框，确认文案写明这一步不可撤销。

**四、这个端点从此算 ledger 写入。** 它退出 `web_router.READ_ONLY_POST_ROUTES`，真删那一步
在任务中心留一条 `empty-folders` 运行记录。

**五、目录枚举给的名单要逐条 `stat` 复核，只留两次都说不在的。** 枚举负责把全库几万行收
到几百条，复核负责定罪（`web_resource_sync._confirm_vanished`）。

## 理由

- 空目录和这些行是同一件事的两半，同一个用户动作产生。分成两个入口的结果是其中一半从来
  没人清。
- 枚举适合当筛子、不适合当判据：网盘挂载上一次 `stat` 就是一次网络往返，全库逐条问不现实，
  所以第一趟复用对账那边的 `scandir`。但它会静默漏报：2026-09-16 本机连测三次 PikPak
  得到 677 条、0 条、452 条，三次交集是空的；其中一次报的 383 条挨个 `stat` 过去，前 200 条
  全都在。那一趟成功返回、不抛错，只是少给了几个名字，连 `unreadable` 都数不到它。
  115 同期三次都是 506 条，复核完仍有 475 条，真删掉的确实删了。
- 复核只作用在几百条的名单上，成本远小于它挡住的损失：照枚举的结果删，一次就能删掉几百行
  文件其实还在的资产，而这一步不可撤销。
- 回收站的行不能靠「清空回收站」顺带解决：那一条是用户对「留不留」的判断，而这里问的是
  另一件事：东西已经不在了。

## 被否决的方案

- **让资源对账扫描把回收站也纳进来。** 它问的是「库里这条还在不在」，等着用户决定去留的
  行混进去会让待办数字失真，用户也会在复核界面上看到一批他已经扔进回收站的东西。
- **另做一个「清理失效记录」按钮。** 用户原话是「网盘同步删除了的都直接删（绑定在扫描空
  文件夹上）」。多一个按钮就是多一件要记得按的事。
- **只删回收站里的那部分。** 文件不在盘上的行在库里也指不到任何东西，按 disposal 分两种
  待遇只会让下一轮长跑批处理接着撞上另一半。

## 后果

- 数据管理页那一屏第一次会删账本行，只读端那份复制来的账本因此不再放行这个端点。
- 任务中心多一类 `empty-folders` 记录，带上删了几条、清了几个目录。
- 文件其实还在的行删不掉：`purge_assets` 先删文件、删得掉才删行，删不掉的整条跳过并进
  `blocked`。这正是这批行该有的保护：还能删掉文件说明它根本不属于这一批。
