# ADR-0080：资源同步一次检查一次执行，失效记录直接永久删除

- 状态：决策二、五被 ADR-0087 取代（决策一、三、四仍有效）
- 日期：2026-09-27
- 取代：ADR-0036（逐条 `stat` 定罪、来源先判在线、回收站的行一起算，这三条沿用）
- 相关：ADR-0052

## 背景

盘与账本对齐原本分在数据管理页的两张卡上：

| | 资源同步 | 空文件夹与失效条目（ADR-0036） |
| --- | --- | --- |
| 文件已不在盘上的在库记录 | 移入回收站 | 永久删除 |
| 文件已不在盘上的回收站记录 | 不管 | 永久删除 |
| 空文件夹 | 不管 | 删除 |
| 不再被引用的缓存 | 删除 | 不管 |

第一行两张卡都管，结果却相反；空文件夹与孤儿缓存各归一边。两次检查扫的是同一批目录，
用户要按两套按钮才算对齐一次，而且得记住哪张卡会把记录放回收站、哪张会直接删。

## 决策

**一、资源同步是唯一入口。** 检查（`/api/resource-sync/scan`，后台作业、逐来源报进度、只读）
每个在线来源报四样：文件已不在盘上的记录数、空文件夹数、读不了的目录数，另报全局孤儿缓存。
执行（`/api/resource-sync/apply`）依次删失效记录、自底向上删空文件夹、清孤儿缓存，任务中心留
一条 `resource-apply` 记录。`/api/data-cleanup/empty-folders` 与那张卡删除。

**二、文件已不在盘上的记录直接永久删除，在库与回收站一样。** 用户原话「网盘同步删除了的都
直接删」。删除走 `purge_assets(missing_only=True)`：删的那一刻再问一次文件在不在，在或答不上
来的进 `blocked`，不碰媒体文件。

**三、执行只认用户看过的那份候选。** apply 必须带最近一次已完成检查的 `scan_id`；缺失、过期
或服务重启过都拒绝，要求重新检查。候选 id 与空目录路径留在作业状态里，不下发前端；执行前逐条
`stat` 复核，中途掉线的来源整条丢弃。

**四、CloudDrive 上 `scandir` 报找不到、`listdir` 为空的目录算空文件夹**
（`web_resource_sync._hollow_directory`）。挂载层给空目录列不出 `.` 与 `..`；2026-09-27 本机
71 个「读取失败」逐个复核全是这种空目录。

**五、详情页「同步删除」（`w_purge_missing`）仍移入回收站。** 它只核对一个目录、一键执行、靠
8 秒撤销兜底；改成永久删除就要补复核与确认框、拿掉撤销，是另一个交互。

## 理由

- 空文件夹、失效记录与孤儿缓存是同一个用户动作（在网盘客户端里删东西）留下的三样残余，一次
  检查就能全部看见。
- 对失效记录，回收站只是多一道：文件已经没了，还原回来的行指不到任何东西。
- 绑定 `scan_id` 让「用户确认的」和「实际删的」是同一份名单；执行时现场全扫会绕开它。

## 被否决的方案

- **保留独立的空文件夹卡。** 两次检查扫同一批目录，按钮分两处只会让一半没人按。
- **失效记录先进回收站再清空。** 用户明确要直接删。
- **apply 没带 `scan_id` 时现场全扫。** 删的名单就不是用户看过的那份。
- **`w_purge_missing` 一并改成永久删除。** 见决策五。

## 后果

- 资源同步执行这一步不可撤销，确认框写明。
- 任务中心的记录键为 `resource-scan`／`resource-apply`；库里早先的 `empty-folders` 行没有标签，
  按原键显示。
- scan-search 忙态动画随它唯一的触发者一起退场。
