# ADR-0061：fc2cmadb 女优栏作为补别名第三站，只收站上主名

- 状态：Accepted
- 日期：2026-09-24
- 修订：ADR-0055「后果」第一条（不接 fc2cmadb 的 `alias_name`）

## 背景

商品名与人物主名的语义不同；来源人物入口给出的主名与曾用名关系，才可用于别名登记。

## 决策

**一、来源层照原样交出人物编号与曾用名。** `sources.fc2cmadb.parse_actresses` 每位交
`{japanese_name, external_id, alias_names}`。`external_id` 落库时按出演者外部编号登记，以后的作品按编号挂回
同一条实体。曾用名串放 `alias_names` 不放 `aliases`：`aliases` 会被资料页合并逻辑直接登记成别名，
商品名就跟着进了账本。`alias_names` 只进来源快照，由补别名后继按自己的判据读。

**二、补别名后继多一站，排在最前。** 她有 FC2 作品（按番号排，最多 3 部）才问 fc2cmadb。
逐部取女优栏，一部两次请求；某部对上就停。

**三、对上的判据是入口，不是写法。** 女优栏里某位人物的主名或曾用名栏出现账本里她的名字，才算她。
这里她的名字不经 `rejection` 筛：入口是她自己那部作品，账本里那句称呼正是站上那一格的写法，
筛掉就永远接不上。女优栏里不止一位对得上时判歧义，一个也不收。

**四、只收站上主名。** 曾用名串一个也不收，商品名现有判据挡不住；站上主名照 ADR-0055 的五、六两条判
（不收的写法、四种不写），被另一条实体占用的记进复核产物，那是合并线索。主名登记之后，本轮再拿它
去搜 minnano-av 与 av_neme，那两站的名字栏补齐其余写法。

**五、归属、撤回与访问。** 批次号、复核产物、撤回脚本都与 ADR-0055 同一套。Cookie 与 429 冷却走
`scraping_access.SourceTransport`；403 与验证页这里补记冷却。站间隔 2 秒，一条后继至多 8 次请求。
女优栏按作品号缓存，站上没有的作品也记下。指纹里只有有 FC2 作品的女优多一项，存量不会因为多了一站被整批重派。

## 后果

- 本站只给出别名，不改规范名。站上主名当规范名更合适的（9333 那种）暂时手工在网页端换，
  自动改名与它的撤回留作后续。
- GirlsDelta（`girlsdelta.com/model/<id>`）评估过，不接入流水线：馆藏里没有这个厂牌的作品，名录与 fc2cmadb
  曾用名串对上的 10 位里，宣传照与封面比脸达到两张过线（`face_match.MATCH_REQUIRED`）的只有 9333 一位；
  9215 只有一张封面，一张过线不够；其余 8 位没有过线，或者封面上的脸打了码。
  它能当单人的佐证链接与头像来源，不当别名证据。
- ADR-0060 的 fc2ppv-db 按第一条的形状交出 `external_id`：女优栏每位链到 `/ja/actresses/<uuid>`，
  uuid 登记成 `fc2ppvdb` 的外部编号。javten 不给演员，不涉及。
- fc2ppv-db 的女优页不接进补别名后继（2026-09-24 实测）：页面数据里有 `aliases` 一栏，但女优列表抽样
  120 位只有 4 位填了；`川北すずね` 那一页是空的，而 fc2cmadb 上她的曾用名有十几个；主名本身也常是卖家
  称呼（`色白スレンダー美女×JD`）。它给不出 fc2cmadb 之外的写法，每问一位还要多花一次过 Cloudflare 的请求。
