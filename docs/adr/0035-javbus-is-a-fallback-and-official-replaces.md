# ADR-0035：javbus 只当备选来源，官方来源单独说话时直接替换现值

- 状态：Accepted
- 日期：2026-09-16

## 背景

ADR-0033 立的规矩是「在线来源只补空」，任何自动写入都不动账本已有的值。2026-09-16 用户
在复核页逐条核对时给出两条判断：

- 「我发现有很多 javbus 的数据是不准的，仅将其拿来作为 fallback」；
- 「单一来源中官方来源直接接受替换」。

队列里的样本证实了第一条。`259LUXU-891` 这一行显示现值 2017-11-26，挑战者是 2026-07-29，
点开来源是 javbus 按 `259LUXU-1891` 取回的，那是另一部片（ラグジュTV 1879）。账本现值来自
官方 mgstage 那一页（`sources/metadata/javinizer-go/259LUXU-891/mgstage.json`，2026-09-01
取得，ラグジュTV 853、2017-11-26），它本来就是对的。

当时队列 148 行的只读试算：18 个候选自报的番号和行上的番号对不上（r18dev 11、dmm 3、
javbus 2、libredmm 2），其中 14 行整行只有这类候选；19 行只剩 javbus 一家；68 行现值非空
而候选全部来自官方来源，这 68 行在旧规矩下只能一条条人工点。

## 决策

**一、候选自报的番号和行上的番号对不上时，整条候选不进队列。** 判据是已有的
`peach.metadata.identifies_code`，落库端早就按它拒收（`_apply_metadata_candidate`），
复核队列这一侧此前没拦。候选全被剔掉的行不再出现在队列里；`candidates_json` 本来就空的行
照旧显示，那是「来源没给」，不是「来源给错」。

**二、javbus 是备选来源（`metadata_policy.FALLBACK_SOURCES`）。** 同一个字段上还有别家可用
时，它的取值不当证据。这一步排在番号日期判据（ADR-0034 决策三）之后：`092415_001` 的发行
日期只有 javbus 报对，先按番号那天定下来，再谈谁退开。

**三、剔完之后只剩官方来源时，自动写入可以替换非空现值。** 「只剩官方」指参与这个字段的
来源全部满足 `SOURCE_SPECS[...].official`（含 official_mirror）。community 来源仍然只补空。
规则名记 `adr-0035-official-replaces-single-source` 或 `adr-0035-official-replaces-N-agreed-sources`。

## 理由

- 番号对不上的候选点了也写不进去：拦截早就在落库端，队列里留着它只是要人再认一遍
  「这个不能点」。实测这类候选占了当时队列的一成二。
- javbus 的错值不是随机噪声，是「搜不到就给首个近似命中」这一个机制的产物：`AR-101`
  给 `STAR-101`、`259LUXU-891` 给 `259LUXU-1891`。有别家在场时它提供不了额外信息。
- 官方页面就是发行方自己写的这部片的事实。番号已经核对过，来源级别是官方，此时把它
  卡在人工那一侧，等于让用户替一条早就排好的信任模型做确认。

## 被否决的方案

- **整源停用 javbus。** 1Pondo、HEYZO 这些片在本机只有它问得到（javdb 与 javlibrary 被
  Cloudflare 与 403 挡住），停用会让这些番号一个字段都补不上。
- **把 javbus 排到字段来源顺序表末位。** 顺序表决定的是排名，不是弃权；末位来源在只有它
  一家时照样是「唯一来源」，仍会进免复核写入。
- **官方来源替换现值也要人点一下。** 那 68 行正是用户当场判断「不必再问」的那一类。用户
  改过的字段归 `user:manual`，`write_owned_fields` 本来就不许自动写入覆盖，这道保护不受影响。

## 后果

- 队列里少掉一批点不动的行，也少掉一批 javbus 与别家的假分歧。
- 自动写入第一次会改掉账本已有的值。能改的只有官方来源，且 `user:` / `review:` 署名的格子
  仍然拒收；回溯从 `review_decision.note` 的 `adr-0035-` 前缀捞。
- javbus 独家收录的片不受影响，它仍是这些番号的唯一证据。
- 替换连同实体关联一起换：厂牌、系列、出演者这一格上 r18、javbus 与 `legacy:asset` 导入的
  旧关联和 `javinizer:*` 同样删掉，人手挂的留着。`ACC-006` 的 r18 条目撞上 2009 年的同号片，
  字段换成 DMM 的值以后，那部片的系列与出演者仍挂在页面上。
