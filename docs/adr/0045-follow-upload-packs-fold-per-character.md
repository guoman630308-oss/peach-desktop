# ADR-0045：关注页把同一批连传的短片按角色归成一包

- 状态：Accepted
- 日期：2026-09-23
- 关系：与 [ADR-0028](0028-follow-groups-fold-within-an-author.md)、
  [ADR-0046](0046-follow-booru-bursts-fold-into-one-work.md) 同为读时计算

## 背景

rule34video 上有一类作品是「一包」：同一个工程导出好几条长度相同的短片，一次连着传上去。
LazyProcrastinator 的一段 KOF 沙滩动画就是 7 条 20 秒的片子，`Angel-handjob`、
`Angel-missionary`、`Mai-blowjob`、`Mai-doggy` 等。标题各不相同，站点不给出处，
发布时间也只有「1 周前」这种天级精度，现有判据没有一条能把它们连起来。

它们的共同点是站内视频 id：这是全站递增的上传序号，这 7 条的 id 只差 4 到 20。

## 决策

来源登记 `sequential_upload_ids=True` 的站点（当前只有 rule34video），五个条件同时成立的
条目归成一组：

1. 同一个来源。
2. 标题开头的角色名相同：取第一个分隔符（` - `、`-`、`[`、`(` 等）之前、不超过 3 个词的部分；
   没有分隔符就取第一个词，跳过冠词和含数字的词（日期、序号）。
3. 按站内 id 排开，相邻两条相差不超过 30。
4. 时长相差不超过 1 秒。
5. 作品分类（`copyright`）有交集。

两条都带 `名字 (作品)` 形式的 general 标签、但一个都对不上时拆开。标题开头是系列名、
角色写在后面的（`Summer Fantasy – Cindy & Lunafreya` 与 `– Tifa & Aerith`）靠这一条分开。
artist 类里同样形式的 `Chloeangelva (VA)` 是配音演员，不算角色。

**不同角色分开，是用户定下的边界。** 同一包里的 Angel 与 Mai 是两组，不是一组。

归组按键合并：一条并进来，和它同键的别站副本一起跟过来。实现是
`follow_store._align_upload_packs`。

同一次改动里，`origin_group_key` 给缺协议头的出处补上 https 再解析，`group_hint` 在读时按
出处重算。实测 rule34.xxx 上同一条推文，一帖写 `https://x.com/…`、另一帖只写 `x.com/…`，
不补协议头就认不出后一帖的出处，两帖会分成两张卡。

## 依据

2026-09-23 在真实 ledger 上只读试算，16324 条可见条目，分组数从 11916 降到 11765，新并出
84 组。

| 判据 | rule34video 归并组 | 减少的卡片 | 抽查结论 |
| --- | --- | --- | --- |
| 只看 id 连号（相差不超过 100） | 139 | 487 | 不采用：一口气补传几十部旧作，id 同样连着，一组 23 条横跨数月 |
| 连号 + 时长相同 + 分类有交集 | 123 | 277 | 不采用：同一包里的不同角色并在一起（Madam M、Jihl、Rinoa） |
| **再加角色名与角色标签（采用）** | 84 | 约 150 | 抽查 28 组未见不同角色并组 |

## 拒绝方案

- 只按 id 连号归组。上传者补传旧作时 id 同样连着。
- 同一包里不同角色合成一张卡。用户明确要求分开。
- 从 general 标签里猜角色。rule34video 不区分角色标签与动作标签，只有 `名字 (作品)`
  这一种写法能认出来，且只作拆开的依据，不作合并的依据。

## 后果

同一角色的一包短片合成一张卡，角标写「N 个视频」。误并的代价是同一角色、同一天、
同样长度的两部作品落在一张卡里；发现误并时收紧 id 间隔或时长容差。
