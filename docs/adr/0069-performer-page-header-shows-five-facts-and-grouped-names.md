# ADR-0069：女优页头展示五项资料，别名按名义分组

- 状态：Accepted
- 日期：2026-09-25
- 沿用：ADR-0067「女优资料落 `performer_profile` 单表」

## 背景

ADR-0067 把 minnano-av 资料表落进了 `performer_profile`，当时写明「界面暂不展示这些资料」。
女优页头只有名字、别名和外链；生日、身材、出道作、出演期间这些认人用的资料，账本里有了，页上看不到。

资料页「別名」一栏的写法带着渠道注记与读音，例如 `橋本真紀（舞ワイフ）`、`篠崎ゆう子 （しのざきゆうこ / …）`。
页头把别名排成一串，分不出哪些是旧名义、哪些是某个渠道起的名字。

## 决策

**一、页头只展示五项**：生日与年龄、身材（身高、三围、罩杯）、出道（日期与片名）、生涯（出演年份，页上写「生涯」）、站上的标签。
它们放在页头右侧的资料表里，宽屏下和身份信息之间隔一道竖线；内容区不到 900px 宽时排到身份信息下面（量的是内容区，侧栏展开时同一个窗口会窄两百多像素）。
血型、出身地、趣味、博客都在账本里，但不上页头。页头是用来认人的，这五项回答「她是谁、什么体型、
什么时候出道、还拍不拍」；再多几项，资料表会比身份信息高出一截，头像两侧留空。
取不到的项服务端不下发，页面也就不画那一格，不写「未取得」。
站上的标签先查资料专用的 `PROFILE_GENRES`，再落回作品标签的映射（`genre_taxonomy` 加复核页的用户决定），
换成 Peach 中文标签，同义的并成一个。资料上说的行业是她本人的经历，风俗按种类、其余行业各译各的，不借作品上
的场景或角色扮演标签；带箭头的风格转变整条保留，一格写了几个的拆开；厂牌与改名移籍这些经历、判为非内容的
都不出，表里未收录的照原文列。那一格只列前四个，余下的收进「+N」浮层。

**二、别名按名义分组。** 名字下面那一行是读音加前三个名字，其余收进「+N」浮层，分组如下：
现名（资料页主名）、旧名义（没有注记的别名）、各渠道名义（按人数从多到少）、其它（账本里有、页上没列的写法）。
注记不另存：`performer_profile.raw_json` 的「別名」原文里就有，读的时候用 `minnano_av.name_entries` 拆。
页面主名不在资料表里，`minnano_av.profile` 把它记在原文的「名前」下。

- `r18:performer` 的条目是读音与罗马字，不是艺名；`javinizer:planning-alias` 是作品给她起的一次性称呼
  （ADR-0038 有意登记，检索要用）。两种都不上页头，账本里照留。
- 规范名是中日文写法时，纯拉丁写法不列，与 `display_aliases` 同一条规则。
- 读音只出一次，排在最前：优先取资料页上的读音；没有资料时，取别名里纯平假名的那条。

**三、只读，不新增写入方。** 页头的视图在 `performer_header`，只读 `performer_profile` 与 `entity_alias`；
资料照旧只由补女优资料后继写，撤回照旧走 `revert_auto_landing.py`。

## 后果

- 迁移 `0036` 应用之前账本里没有这张表，女优页照常打开，页头只是没有资料表，名字行只用账本别名。
- 补女优资料后继取到一位，她的页头就多出右侧资料表和分组别名；没取到的只有名字行和图标外链。
- `performer_profile` 只存一段出演期间（`debut_year` 到 `active_until`）。站上写了几段的（`2015年〜2018年、2019年〜`），
  规整规则只读第一段，页头会显示成已结束；要改得改 `minnano_av.profile`，原文在 `raw_json` 里，可以就地重算。
