# ADR-0027：内容产地是独立一维，JAV 是它的投影

- 状态：Accepted
- 日期：2026-09-13

## 背景

账本里没有任何一列说得出一部片是哪来的。「是不是 JAV」由 `catalog_rules.is_jav_asset`
和它在 SQL 侧的孪生 `JAV_ASSET_PREDICATE` 推出来，判据两条：番号形状像，以及有发行证据
（`studio`、`release_date`，或挂着 performer／studio／series 实体之一）。

番号形状是日本厂牌的写法。韩国 MIB 的 `CA-103`、国产麻豆的 `MDX-0123` 和日本的 `MEYD-911`
在形状上没有区别，发行证据那几条它们也全都满足。更糟的是那份证据往往是刮削自己写进去的。

`is_korean_mib_code` 那份前缀名单早就认得出 MIB，但它只接在刮削入口上，封面抓取、海报
裁切、元数据策略、编目、自动批准都读它，唯独分类口径没有。这不是名单不够长，是缺一个维度：
「这批片是哪个发行体系的」从来没有地方存。

创作者内容可能没有番号可推，产地需要从创作者身份取得。

## 决策

**一、产地是 `asset` 的真相字段 `region`，取值 `jp`／`kr`／`cn`／`west`／`other`，空串是未判定。**

它说的是发行体系，不是拍摄地也不是演员国籍：JAV 里有欧美女优，欧美片里有亚洲演员，按人
判会把同一个厂牌的片拆到两个产地去。

取值集合写在 `src/peach/regions.py`，不写成 SQL `CHECK`：将来要把港台从国产里拆出来，改一个
Python 常量就够了，不必为加一个取值再迁一次账本。不细分到国家一级，因为拆开之后每条规则都
要回答「捷克拍的美国厂牌片算哪国」，而这个问题对使用者没有意义。

未判定与 `other` 分开记。只能记「是什么」的话，「还剩多少片没判产地」这个数永远算不出来。

**二、`entity.region` 承载厂牌与创作者这一层。**

同一个创作者的作品可复用实体上的产地，不必逐条重复判定。

**三、有效产地按三层取第一个有值的：`asset.region` → 实体投影 → 番号推断。**

表达式写在 `web_catalog.effective_region_sql()` 一处，页面标的产地、筛选器筛出来的那批、
JAV 页收不收一部片，全读它算出来的同一列。推断结果不写进账本，所以必须在每次查询时算，
那就只能有一处算法。实体那一层 `studio` 优先于 `creator`：一部片同时挂着两者时发行体系
由厂牌定，转载它的创作者可能是另一个国家的人。

**四、`is_jav_asset` 与 `JAV_ASSET_PREDICATE` 只是产地的投影：产地判过且不是日本，一概不是 JAV。**

未判定维持原有口径。这一列绝大多数行还是空的，拿「没判过」当「不是日本」会清空整个 JAV 页。

**五、推断只认推得出的那部分，日本不在其中。**

韩国 MIB 前缀、国产厂牌前缀、西片的「厂牌.发行日」形态各有名单或形状可依。把「剩下的都算
日本」写成规则，等于让每一个没收录的国产厂牌自动变回 JAV，正是这次要修的毛病。

**六、用户的判定走 `field_owners`，归属 `user:manual`。**

入口是批量操作 `region`（`/api/batch`），按选中的一批片一次判完。产地是真相字段，用户这一笔
要压得住后面每一轮刮削与推断，归属列是它唯一的凭据。写错的取值直接拒绝而不是当成未判定：
`normalize_region` 对认不出的写法退回空串是给查询参数用的，批量那一路跟着它走的话，一次拼错
就成了一次静默的清空。

## 后果

- MIB 与国产厂牌的片立刻离开 JAV 页，不需要先回填一轮账本：推断这一层不落库，查询时就生效。
- `asset.region` 与 `entity.region` 的已有行全部留空。推断结果是候选，把猜出来的产地直接写进
  真相字段，等于用一次批量脚本替用户做了他还没做的判断，而这一列猜错了不报错，只是片再也找不到。
- 产地分面带未判定那一档，它就是这项人工活的待办数。
- 番号前缀名单追不上新厂牌，这是接受的：推不出来的走人工，推错了才是要命的。名单只在
  `regions.py` 与 `catalog_rules.KOREAN_MIB_PREFIXES` 两处，后者是演员名缩写、会随片源变长，
  两份各自维护。
