# ADR-0055：女优艺名按两站名字栏确定性落库，不经候选

- 状态：Accepted
- 日期：2026-09-24
- 依据：ADR-0052（实体层证据充分即落库）、ADR-0053（后继派单与存量补派）

## 背景

同一位女优换过艺名、在不同渠道挂着不同名字是常事。实体 9220「神山ももか」在账本里一条别名
都没有，而 minnano-av 699633 那一页的资料表列着她在 FC2、着エロ、天然むすめ 用过的写法和现用名
`雲母そら`，av_neme 的「雲母そら」人物页也列着同一串。按名字链找头像、搜作品、判合并时只拿着
一个名字在走，图库里存在另外几个写法下的图整批出不来。

这类证据有确定的判据，不需要人逐条看，按 ADR-0052 直接落库。

## 决策

**一、后继 `performer-alias`（补女优别名）。** 处理任务结算时和补头像、补厂牌一起声明：新登记的
女优一人一条，排在存量前面；存量按作品数从多到少补。一轮 `MAX_FOLLOWUPS`（64）条里，存量给
补别名留至多 16 条（`STOCK_SHARE`），其余先给补头像、再给补厂牌。一条要问两站、耗时十来秒，
走写账本那条串行通道，给多了会把厂牌那几条挤到很后面。跑完记下指纹（她的名字链与 minnano-av
编号），没变不再派。

**二、入口。** minnano-av 先用账本里已有的 `entity_external_ref` 编号；没有才按名字链检索，结果表
里与这个写法精确同名的行只指向一个编号才采信（同一人几个别名各占一行，按编号去重）。av_neme 按
名字站内搜索，读前三张页名像人物页的结果；恰好一张列着她才算，两张以上判歧义并停手。

**三、双向核对。** 账本里她的某个名字（规范名或已有别名，本身得是收得下的写法）必须出现在那一页
的主名或别名栏里。

**四、只读名字栏。** minnano-av 读资料表 `act-profile` 里的「別名」行；av_neme 读人物页第一节
「プロフィール」里的「名前(女優名)」「旧名義&別名」「名前(別名)」，且页名必须等于主名。读音和
`(FC2)`、`【旧名】` 这类括号注记剥掉；作品小节里的素人名义不读。

**五、不收的写法。** 三个字以内的纯假名（`そら`、`みく`）会命中别人；罗马字写法；带 `?`、`▲`、
`不明` 的；带 `ちゃん`、`さん` 这类敬称的一次性称呼（`metadata_alias_resolve.is_planning_alias`）；
`145cm色白お嬢様` 这类描述性称呼（`is_descriptive`，ADR-0054）。这些写法也不拿去检索。

**六、四种不写**，与 `scripts/apply_alias_candidates.py` 同一口径：已有；被另一条女优实体占用
（那是两条该不该合并的问题，记进复核产物）；统称已变；查无此人。

**七、归属与撤回。** `entity_alias` 没有批次列，`source` 直接存批次号
`auto:performer-alias@<任务行 id>`，与 `avdb-actor-mapping@<rev>` 的形状一致，置信度 1.0。
`scripts/revert_auto_landing.py --source auto:performer-alias` 撤回这个来源的全部，
加 `--batch auto:performer-alias@<id>` 只撤一批。指纹不计这条后继自己写的别名，撤回之后她的
名字链回到写之前，存量补派不会原样再落一遍；判据修正后想重跑，删掉
`generated/provider-cache/followup-attempts/` 下对应的记号即可。每一轮的判词逐条写进
`generated/performer-alias-landing.csv`。

**八、访问约束。** 两站都走页面缓存与站间隔（minnano-av 3 秒、seesaawiki.jp 2 秒，进程内共用），
一条后继每站至多 8 次请求。撞上 429、403 或机器人验证就记进 `scraping_access` 的冷却，本轮与
之后的后继在冷却期内都不再问这一站，结论写「未取得」。验证页不进缓存。

## 后果

- fc2cmadb 的女优栏由 ADR-0061 接成第三站，只收站上主名，`alias_name` 那一串仍不收。
- 被占用的写法只记不写。复核产物里的这些行是合并候选的来源，处理方式仍按合并流程。
- 第二圈检索：一站登记了新写法、另一站第一圈没命中时，拿新写法再搜那一站一次。
