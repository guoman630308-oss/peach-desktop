# ADR-0056：图库同名多张时按封面人脸认人

- 状态：Accepted
- 日期：2026-09-24
- 修订：ADR-0040 第七条（补头像的判据）、ADR-0053 第三条（女优的指纹）

## 背景

补头像后继（`peach.avatar_followup`）对图库的规则是：按她整条名字链（规范名加别名）在
gfriends 里只找出一张、且过尺寸门槛才装，找出多张一张都不装，退到封面截脸。

同一个人可能被多个图库目录分别收录；短单名也可能命中不同的人。名字无法独立判断照片身份，需要人脸证据。

## 决策

**一、拿封面上的脸认图库里的脸。** 比对用 OpenCV 的 SFace（`cv2.FaceRecognizerSF`，
opencv_zoo 定版模型 `face_recognition_sface_2021dec.onnx`），与检脸用的 YuNet 同属一个包、
同一套取法：放 `peach-data/tools/sface/`，按需下载，校验 sha256。参照是她单人作品封面上
截到的脸（`avatar_cover_face`，与封面截脸那一档同一份），按脸宽取前三张。

**二、判据。** 候选与参照各取主脸、按五个关键点摆正后提特征，算余弦相似度。候选要和
两张参照都过 SFace 官方阈值 0.363 才算她本人；参照只截得出一张时，和那一张过线即可。
三张参照时过两张就算。阈值不自己调：本库没有带真值的样本集。

**三、挑哪一张。** 没过尺寸门槛（`acceptable_avatar`）的候选不比；其余照图库现有的先后
（`gfriends.quality_key`）逐张比，第一张过线的装上，后面的不再取。不按像素挑：图库靠后的
大库原图只有两三百像素、靠 AI 放大到五百以上，按像素排会让它们抢到片商原图前面。

**四、退路。** 取不到比对模型、她没有单人作品封面、封面检不出脸或提不出特征、没有一张
候选过线，一律不装图库的图，照旧退到封面截脸。取不到模型的那一次不记进
`followup-attempts`：那一次的结论取决于有没有网，不取决于她的作品和名字。

**五、留证据。** 装上的头像边车在原有来源字段旁加 `face_match`：模型名、阈值、要求过线
的张数、每张参照封面的番号、作品 id 与分数、候选总数与实际比过的张数；`source_kind` 记
`gallery_face_matched`。比对时取来的候选图只按地址存进图库缓存，不写成她取过的图。

**六、指纹加别名数。** 女优的指纹从「作品数」改为 `作品数:别名数`。别人补上别名之后，
她在图库里能命中的名字变了，存量补派会让她重新排队。旧格式的记号全部不再匹配，存量里
缺图的女优各重试一次。

## 后果

- 只有一张参照、且那张封面的脸被贴纸、口罩或马赛克挡住时（FC2 封面常见），过线的分数
  可信度较低。装上的图边车里带
  `source_kind: gallery_face_matched` 与每张参照的分数，可以按它筛出来复核、整批换掉。
- 没有单人封面的那一大半仍然装不上，要解开它们需要别的参照（官方资料页人像等），不在本 ADR 内。
- SFace 模型 37 MB，只在第一次真要比对时下载。
