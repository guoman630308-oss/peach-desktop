# ADR-0054：FC2 卖家记进 label，描述性称呼不建女优实体

- 状态：Accepted
- 日期：2026-09-24
- 相关：ADR-0018、ADR-0029、ADR-0038、ADR-0052

## 背景

自动落库按 ADR-0018（单一社区来源补空）与 ADR-0029（本地 NFO 补空）落下了两类不该有的
实体。

- **卖家成了厂牌。** amane 的 FC2 爬虫把卖家名填进 studio，它写出的 NFO 经本地 NFO 规则
  落库会把卖家误建为厂牌实体。
  Peach 自己的 FC2 解析器早就把厂牌钉成 `FC2-PPV`、卖家放 `label`（`sources/fc2.py`），
  但这个约定只在那一个解析器里成立，别的入口各写各的。
- **描述性称呼成了女优。** fc2cmadb、javdb 的素人条目常把标题里的称呼填进出演者栏：
  `145cm色白お嬢様`、`人気焼肉店の看板娘`、`美女6名`。照抄就是一个永远找不到头像、
  永远对不上别处记录的女优实体。

## 决策

**一、FC2 番号的厂牌一律是 `FC2-PPV`。** 来源给的其他名字当卖家，改记进候选的 `label`；
`label` 只是证据，不是真相字段。归一放在解析候选那一层（`_fc2_seller_as_label`），
复核页与自动落库都经过这里，落库入口再兜一道。本地 NFO、amane 桥、javdb，以及以后新增的
来源，都走这同一处。`FC2`、`FC2 PPV` 这类平台自己的写法照样折成 `FC2-PPV`，但不算卖家。

**二、描述性称呼不是艺名。** `metadata_alias_resolve.is_descriptive` 认下面这些写法：

- 身高、人数（`169㎝`、`6名`）；
- 感叹号；
- 外貌与身份用词（`スレンダー`、`女子`、`看板娘`、`先生`、`ギャル`、`OL`……）；
- 宣传语（`の様な`、`働く`、`人気`……）。

`stage_name` 遇到这些写法返回 None：整条出演者候选先走企划名义解析（ADR-0038），用素人
wiki 快照换成正式艺名；换不出就交人工，不建实体。人工批准不受这道门槛约束。
`OL` 区分大小写，免得撞上
`Ssol`、`Cola酱`。

**三、存量按新判据改一遍。** `scripts/repair_fc2_sellers_and_descriptive_names.py` 默认只列
计划，`--apply --backup` 才写：

- FC2 作品的厂牌改成 `FC2-PPV`，关系改挂过去；
- 再没有作品的卖家厂牌实体删掉；
- 描述性称呼女优只删那些关系全部由自动落库写下的，连同 `演员:` 标签一起删；
- 撤掉对应的自动批准决定，让这几部片按新判据重新排进人工队列；
- 头像文件挪进 `avatars-superseded/`，不删。

## 后果

- 新扫到的 FC2 作品不会再长出卖家厂牌，也不会再长出描述性称呼女优。
- 那几部片的出演者重新出现在复核队列里，其中有快照的会自动换成正式艺名。
- 词表是枚举，会有漏网的描述性称呼；漏掉的仍会建成实体，照这份 ADR 补词、重跑存量脚本即可。
