# ADR-0020：账本副本「写过没有」的判据分三层

- 状态：Accepted
- 日期：2026-08-25
- 关系：细化 ADR-0017 的账本复制边界

## 背景

排查的起点是一个体验问题：macOS 这台是只读端（写入端点一律 409，不跑任何写回账本的脚本），
却被 `local_dirty()` 判成「本地有未回写的改动」，于是 `plan()` 返回 `conflict`，
每次同步都要人工选边。

**原假设是错的。** 实测证明只读端不会弄脏主库：拉取到第 30 代之后重启服务，跑完
11 个读端点再加一次被拒的写入（409），主库 `mtime` 一位都没变，`local_dirty` 保持
`False`、`plan` 保持 `in-sync`。历史上那一次变脏另有原因，且**没有造成任何逻辑差异**：
集合差显示本地相对共享只多 96 条 asset 和 9 条 entity，而这些都是 Windows 在
第 29→30 代之间删掉的广告条目，本地一条独有的新增都没有。

但顺着这条线量判据本身，量出了两个真问题。在临时库上分别构造四种情形：

| 情形 | `(size, mtime_ns)` 判据 | 实际是否写过 |
| --- | --- | --- |
| 只改 mtime（内容不变） | dirty=**True** | 否 → **误报** |
| 写入后帧留在 WAL 里 | dirty=**False** | 是 → **漏报** |
| checkpoint 回写 | dirty=True | 是 → 正确 |
| 只读打开关闭 | dirty=False | 否 → 正确 |

误报就是眼前这个体验问题：内容中性的 checkpoint、备份工具碰一下时间戳，都会让只读端
被判成脏，同步退化成人工选边。

**漏报要严重得多，是数据丢失。** 已提交但还在 WAL 里没回写的事务完全不改主库文件，
大小和 mtime 一位都不变。这种状态在「还有连接开着」和「进程崩溃过」时真实存在。此时
`plan()` 会判成可以 `pull`，而 `copy_database()` 明确会 `unlink` 掉目标的 `-wal`，
那些已提交的事务就此永久消失，并且不会有任何报错。

## 决策

`local_dirty()` 按从便宜到贵三层判定：

1. **WAL 载荷**。`-wal` 的归一化大小与标记记录的不一致就是写过。归一化的意思是
   「不存在」和「小于一个 WAL 头（32 字节）」都算 0，因为只读连接打开数据库时 SQLite 会建一个
   0 字节的 `-wal`，关闭时又可能删掉它，不归一化的话光是浏览就会被判成写过。
2. **快路径**。主库指纹和 WAL 载荷都与标记一致就是干净，不做任何哈希。绝大多数调用走这里。
3. **内容摘要**。主库大小不变、只有 mtime 变时，用 SHA-256 把「碰过」和「写过」分开。
   只在前两层无法判定时计算摘要。

`Marker` 因此多两个字段 `digest` 与 `wal_size`。旧标记两个字段都没有，那两层自动跳过，
行为退回原来的样子，不需要迁移，也不需要重新播种。

共享副本的标记不算摘要（`write_marker(..., with_digest=False)`）：只有本机副本会被
`local_dirty` 检查，给共享副本算摘要等于重复读取整份 SMB 副本。

## 拒绝方案

- **SQLite 头部的 change counter（字节 24–27）。** 直觉上正是为此设计的，实测在 WAL 模式下
  四种情形里**全程不变**（一直是 2），包括真实写入。WAL 模式不走这个计数器，用它等于没判。
- **`PRAGMA data_version`。** 只在同一连接内反映别的连接提交过，绝对值跨进程无意义，
  没法写进标记。
- **每次都算摘要。** 127 MiB × 每次 `plan()`，为了一个绝大多数时候走快路径就能定的判断。
- **同步前先 checkpoint 再比较。** 那是写操作，`observe()` 这条只读路径不能有副作用。
- **继续只看 `(size, mtime_ns)`。** 漏报会静默丢数据，不是可以接受的默认。

## 后果

只读端不再因为时间戳被碰过就退化成人工选边；同时，真有未回写事务时同步会挡住，
而不是安静地把它们删掉。代价是标记多两个字段、判据多两层分支，以及在「大小相同、
mtime 不同」这一种情形下多花约 78 ms。

判据本身仍然是文件级的，不比对逻辑内容：两次不同的写入如果恰好产生相同的 WAL 大小
且主库摘要相同，仍然会被判成干净。真要做到逻辑级比对得逐表算校验和，那是另一个量级的
成本，当前没有证据表明需要。
