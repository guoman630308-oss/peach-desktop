# ADR-0083：订阅源页签按女优名订阅，账本里没有的就新建

- 状态：Accepted
- 日期：2026-09-27
- 关系：放宽 [ADR-0047](0047-feed-subscriptions-enter-from-the-performer-page.md)
  决策一「订阅只从人物页的『订阅新作』开关进」；「页面不送地址」与「只有 JavDB 演员页一类」不变。
  与 [ADR-0081](0081-performer-profile-followup-binds-javdb-actor-ids.md) 共用演员卡的判身份规则。

## 背景

ADR-0047 把订阅入口收到人物页的开关上，前提是想订的人已经在账本里。实际用法里常常不是：
看到一位新人想盯她的新作，她在本机一部作品都没有，人物页不存在，开关无处可点。
唯一的办法是先弄到她的一部作品、等编目认出她，再回人物页开订阅。

关注管理页的「关注列表」有自己的「添加关注」，按链接、名字或 id 查找候选再登记。
「订阅源」页签只有清单，用户要的是同一件事：给一个名字，就能订。

`feeds.match_performers` 写过「这里只做关联，不建实体：凭一个来源给的名字往账本里加一个人，
等于让未经复核的断言变成实体」。那条理由针对的是 Feed 拉回来的作品上写的演员名——来源说的。
按名字订是用户当场看着 JavDB 的演员卡点选的，是用户说的，不是来源说的。

## 决策

**一、订阅源页签加「添加 JAV 订阅」。** 输入女优名，服务端到 JavDB 的演员搜索
（`javdb.SEARCH`，走 Feed 同一条 `SourceTransport` 与主机限流）拿演员卡，页面列出每张卡的
站内 id、站上全部写法与记录类型。查找只读不写；`GET /api/feeds/lookup?q=`。

**二、页面仍不送地址。** 登记时送的是勾选的演员 id（`POST /api/feeds/source`，
`action: follow-name`，`{name, ids}`），地址由服务端按 id 现拼（`entry_links.javdb_actor_pages`），
和人物页开关走同一段 `feeds.follow_entity`。ADR-0047 决策一放宽为「订阅从人物页开关或
订阅源页签按名字进」，其余不变。

**三、这位是谁，按这个顺序定。** 所勾的 id 已经在账本里谁名下就是谁；都没主时按名字认账本里的
正名或唯一别名（`entities.resolve_entity`）；还认不出就新建一位 `performer`。几张卡分属账本里
不同的人时拒绝并列出，让用户先去合并。查找结果里就把「会挂给谁」说出来（`held_by`、`known`），
不让人点了才知道。

**四、预勾只给同一个人。** 卡上写法与输入的名字同键（`match_key`）的那几张，按 ADR-0081 的
`one_person` 判是不是同一位（每种记录类型至多一张）：是就先勾上，站上同名不止一位就一张都不勾。

**五、来源写 `user:feed-follow`。** 新建实体的 `metadata_json.source` 与绑上的
`entity_external_ref.metadata_json.source` 都记这一个，不冒充 `auto:performer-profile`；
按来源整批撤回时（ADR-0052）分得清哪些是用户当场点的。卡上的其他写法不写进 `entity_alias`，
那是补女优资料后继（ADR-0067）的事。

## 被否决的方案

**只允许订账本里已有的人。** 解决不了背景里的场景：她还没有作品时正是最想盯新作的时候。

**由查找结果直接建，不让用户勾。** 站上同名的人不止一位时会挂错人；`one_person` 只判
「名字对得上的这几张是不是同一位」，判不了「就是用户要的那位」。

**把卡上的写法一并写进别名。** 那些写法是站上的，不是用户点的；ADR-0081 已让后继按自己的
来源去写，两处各写一份会让撤回时分不清归属。

## 后果

- `KIND_LABELS` 里演员页那一类改叫「JAV 订阅」：类型标签说的是用户订的东西，不是抓取实现。
- 按名字新建的女优没有作品：`/api/entity` 打得开她的资料页并带订阅开关，但作品索引与搜索建议
  都 join 作品，她只出现在订阅源表与新作那一行里，直到有作品认到她名下。
- `performer_profile_followup._bind` 改公开为 `bind`，两条路共用同一段绑 id 的写法。
- `tests/test_feeds_web.py` 的 `FeedFollowByNameTest` 钉住候选、预勾、归属顺序与拒绝条件。
