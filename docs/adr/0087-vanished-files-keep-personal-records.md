# ADR-0087：盘上消失的文件标「已消失」，个人记录留下并接到新版本

- 状态：Accepted
- 日期：2026-10-01
- 取代：ADR-0080 决策二、决策五（决策一、三、四仍有效）
- 相关：ADR-0052、ADR-0080

## 背景

六张表记的是用户自己的行为：`asset_preference`（0006，喜欢与打分）、`watch_queue`（0003，稍后看）、
`playlist_item`（0017）、`asset_quality_goal`（0011，寻找更好版本）、`activity_event`（0024，观看
历史与高潮的 `position_seconds`）、`asset_tag_preference`（0024）。它们对 `asset` 一律
`ON DELETE CASCADE`。ADR-0080 让资源同步对盘上已消失的文件直接 `purge_assets`，详情页「同步删除」
把行移入回收站、清空时同样级联，这些记录随行一起永久删除，用户看不到删了什么。

网盘上文件消失多半不是不要这部片：换成高清版、整理目录、115 清理都会让旧路径消失，作品还在馆藏里。
「寻找更好版本」最典型：真换上更好的版本，旧版的喜欢、打分、观看历史与目标本身一起被删，新文件
从零开始。

SakuraMedia 的原则是「记录比文件重要」：时刻对媒体 `SET NULL` 并快照番号，删媒体不删记录。用户
2026-10-01 决定采用这条原则，取代 2026-09-27「网盘同步删除了的都直接删」。

## 决策

**一、带个人记录的消失行不删，标 `asset.disposal='vanished'`。** 资源同步执行时，文件已不在盘上的
在库行按有无个人记录分两档。个人记录是上述六张表任一有行，或 `asset` 行自己的 `rating` 非空、
`o_count`／`play_count` 大于 0、`last_played` 非空：

| | 资源同步执行 | 详情页「同步删除」 |
| --- | --- | --- |
| 带个人记录 | 标 `vanished` | 标 `vanished` |
| 不带个人记录 | 永久删除（ADR-0080） | 移入回收站 |

`vanished` 行对列表、搜索、统计、推荐与 Feed 落地都算不在库，行上的快照图保留，供孤儿记录列表认片。
详情页的 8 秒撤销对两档都有效。检查报告分开报两档计数，确认框写明哪一档不可撤销。

**二、新文件登记时接回记录。** 扫描登记新文件时依次判（标 `vanished` 的那一刻也按 2、3 两条找已在库
的另一个版本，唯一命中当场接回，应对新版本先入库、旧文件后消失）：

1. 同一 `(location, path)` 有 `vanished` 行：文件回来了，清掉 `disposal`，不新建行。
2. `normalise_code_key` 后的番号对上 `vanished` 行：同番号只有一个新文件就搬；有多个时选时长最接近
   的，分不出就留给人在孤儿记录列表里选。
3. 无番号的创作者视频按「创作者 + 文件名主干 + 时长」匹配，规则同上。

搬运把五张表的行改指新行，新行已有同一键的记录时以新行为准；`asset_quality_goal` 搬到新行并标
「已替换」关闭（`replaced_at`），不当作新行的待找目标。`asset` 行上的四列并到新行：`rating` 新行为空
才取旧值，`o_count`、`play_count` 相加，`last_played` 取较晚的。搬完删旧行。每次搬运按 ADR-0052 记一个
批次（`record_rehome`，来源 `auto:vanished-reattach`，手动接回为 `user:reattach`），存下旧行快照、
各表搬动的行与新行四列的原值，整批撤回（`scripts/revert_auto_landing.py`）时按快照重建旧行并改回指向。

**三、数据管理页给孤儿记录列表。** 列出全部 `vanished` 行与它们带的记录，可手动接到某个文件，或彻底
删除；彻底删除走 `purge_assets`，确认框写明不可撤销。

**四、回收站照旧。** `disposal='trash'` 的行是用户主动丢弃的，清空回收站连记录永久删除；回收站里
文件已经消失的行，资源同步照 ADR-0080 永久删除。

## 理由

- 个人记录挂在作品上，文件只是作品的一个版本；番号是唯一跨版本稳定的键。
- 不删行就不用重建六张表：前四张的主键含 `asset_id`，后两张 `asset_id` 是 `NOT NULL`，改成
  `SET NULL` 都要重建表。
- 不带个人记录的行留着没有用处，照旧删除，资源同步的行为对大多数行不变。

## 被否决的方案

- **六张表改 `ON DELETE SET NULL`。** 要重建六张表；记录脱离 `asset` 后丢了番号与标题，接不回去。
- **维持 ADR-0080，消失即删。** 代价是每次换版本都丢记录。
- **消失行进回收站。** 回收站的语义是「用户不要」，清空就丢。
- **按文件指纹接回。** 消失的文件读不到，算不出指纹。

## 后果

- `idx_asset_disposal_id` 是 `WHERE disposal IS NOT NULL` 的部分索引，`vanished` 行会进索引。
  `src/peach` 里 19 个模块引用 `disposal`，用 `disposal IS NULL OR disposal<>'trash'` 判在库的查询都要
  排除 `vanished`；实现时逐个核对，并补测试守住「`vanished` 行不出现在列表、搜索与统计里」。
- 资源同步执行对带个人记录的行变得可撤销，对其余行仍不可撤销。
- `vanished` 行不能移入或移出回收站，接口回 400；播放列表照旧列出它们，标「已消失」且不可播放。
- 撤回接回批次时新行四列还原成接回前的值，接回之后新增的播放计数会被覆盖。
- 迁移 0041 加 `asset_quality_goal.replaced_at` 与 `record_rehome`。
