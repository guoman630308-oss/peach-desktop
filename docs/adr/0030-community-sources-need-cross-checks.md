# ADR-0030：官方渠道落空时用 AVBase 与 javdb 补，社区来源互相印证才免复核

- 状态：Accepted；封面只有一个图源时的处理由 ADR-0032 修订，资料的决策一由 ADR-0034 取代
- 日期：2026-09-14

## 背景

既有库采集只问 r18.dev 要资料，封面只走官方渠道（DMM CDN、MGS、Prestige）。独立包读本地
JAV 文件夹实测，问题清单里大量「请检查采集来源后重试」，用户逐条在 javdb 上都搜得到。

- r18.dev 没有收录的番号（下架片、素人系）资料直接落空；
- 官方封面宽度不足 700px 或是 DMM 的「准备中」占位图（302 到 `now_printing`，590×800）时，
  `best_cover` 报「候选都不是可用封套」，落进采集任务的通用失败分支，文案只剩一句「请检查采集来源」；
- 素人系官方图只有 300×300 左右，门槛一卡就是没有封面。

2026-09-14 实测：AVBase 搜索页 `/works?q=<番号>` 能直接取得，`__NEXT_DATA__` 带作品在各店铺的
商品条目；javdb 搜索页与详情页也能取得。两家的值并不总是对的：`ABW-358` 在 javdb 上的发行日期
是 MGS 的上架日，标题带 MGS 附注，演员栏混着男优。

决定：用 javdb、AVBase 补；官方取不到时要多方比对求证；小封面比没有封面好。

## 决策

**一、资料。** r18.dev 说没有或出错时，按顺序问 AVBase、javdb，两家的值各自进候选。候选 CSV
的 `source_profile` 为 `library` 时，`metadata_auto_apply_candidate` 对只有社区来源的字段多一道
门槛：至少两家来源给出同一个值才免复核，否则进人工。r18.dev 与本地 NFO 的规则不变。两家各记
「没有」的记忆（`community` 键），一周内不重问。

**二、封面。** 官方渠道先取；宽度 ≥700px 直接用。取不到或只有小图时，取 AVBase 与 javdb
给的封面，按 dHash（9×8，宽高比差 ≤4%、指纹差 ≤10 位）比对，只有在两个图源（DMM、DUGA、MGS、
javdb 各算一个；官方小图也算一个）上都出现的图才用，多张时取像素最大者。社区来源都对不上时
退回官方小图（宽度 ≥240px）。`.scraping.json` 记 `verified_by` 图源。

**三、礼貌访问。** javdb 主机间隔 5 秒；javdb 与 AVBase 回 403 时整源暂停（javdb 24 小时、
AVBase 6 小时），不换出口、不绕验证页。

**四、问题清单写原因。** 未归类的失败也写出具体原因，例如「封面未取得：官方封面只有缩略图或
占位图；社区来源的封面没有第二个图源能对上」「外部资料未取得：r18.dev：来源返回 HTTP 503」。

## 理由

- 社区站抄录官方数据时会带进别的店铺的日期和附注，两家独立抄录还一致，出错的概率才低到能跳过复核。
- 封面是图，比文字更好比：同一张图在两个图源各出现一次，就不是 javdb 把别的片挂错了。
- 小图至少让卡片认得出是哪部片；有更大的、经过印证的图时照样换上。

## 被否决的方案

- **javdb 单家的值免复核。** 用户 2026-09-04 允许单一社区来源补空，是针对已登记来源的批量候选；
  采集任务里 javdb 出现的恰恰是官方都没有的片，身份更弱，一家之言放行就会把 MGS 上架日写成发行日。
- **社区封面不比对直接用。** javdb 偶有把合集或同系列别作的图挂到番号下，没有第二个图源无从发现。
- **只接受 700px 以上封面。** 素人系官方就没有大图，结果是整批没有封面。

## 后果

- 采集每部官方落空的片多 1～3 次请求；javdb 5 秒间隔让这类片每部至少多等 10 秒。
- 只有 javdb 一家收录的片，资料全部进人工复核；封面若没有第二个图源，只能用官方小图或没有封面。
- `/scraping` 页多出 JavDB 与 AVBase 两项来源连接设置。
